play.google.com/console →「アプリを作成」
📷 この画面のキャプチャは無し（枠を作る前は中に入れない）。表どおり入力 → 申告2つにチェック →「アプリを作成」。
アプリ名identity.displayName
例: 君斗りんくのWEBサイト健康診断 / リバースハック WEB健康診断
パッケージ名stores.playPackageName
例: com.kimito.link.webhealthcheck / com.reversehack.webhealth
⚠️ AAB と完全一致。あとから変更不可
言語日本語 – ja-JP
種別アプリ / 無料
2
ダッシュボードを確認 人間
ダッシュボードで「アプリのセットアップ」を 5/5 に
📷 kimito 実証: 作成直後。申告タスクが並ぶが先に AAB を上げてOK
📷 RH 実証: 製品版審査送信後のダッシュボード。「更新ステータス: 審査中」＋「より多くのテスターでテスト」（1/5）が並ぶこともある
💡 適当にぽちぽち NG。 各申告は保存/送信まで押さないと未完了のまま。 RH ダッシュボード / kimito ダッシュボード が 5/5 になるまで「審査に送信」はグレーのまま。
3
内部テストに AAB を載せる 人間（3分）
内部テスト → リリースを作成
📷 ライブラリから AAB にチェック →「リリースに追加」
📷 リリースノートは <ja-JP>…</ja-JP> の中身だけ書き換え
📷 黄色の警告（難読化なし等）は無視して保存。赤エラーだけ止まる
内部テストの審査送信 ≠ 製品版公開。本番はStep 6。内部テストだけでは「12人×14日」の本番アクセス要件は満たせない（Step 7 参照）。
4
2つの値を AI に渡す コピペ2回
これで playAppId と assetlinks が自動配線される
① playAppIdConsole URL の /app/【数字】/ 部分 → stores.playAppId
② SHA-256 アプリの署名 → Digital Asset Links JSON の 📋 コピー → AI が assetlinks.json 更新
⚠️ assetlinks に入れるのはアプリ署名鍵（アップロード鍵と取り違えない）。RH 実証: ブランドごとに fingerprint を分離（app.config.reverse-hack.json の android.sha256CertFingerprints）。📋 コピーボタン必須（スクショだと指紋が切れる）。
RH: ディープリンク緑チェックは v7 AAB + assetlinks 修正後に ディープリンク → 検証を再試行。
5
アプリのコンテンツ申告 人間（順番固定）
アプリのコンテンツ — 回答は docs、操作は下の順
📷 ストア掲載: テキスト・画像は store-assets/ から API または手動アップロード
📷 アプリのコンテンツ: ログインの詳細・プライバシー・広告・レーティング等

この順で埋めて、各画面で必ず「保存」または「送信」:

  1. プライバシーポリシー — RH: partner…/privacy / kimito: privacy-policy.html → 保存
  2. アプリのアクセス権 — 「特別なアクセス権なし」→ 保存
  3. 広告 — 「広告なし」→ 保存
  4. データの安全性 — 「収集なし」→ 最後まで → 送信（保存だけだと未完了）
  5. コンテンツのレーティング — IARC アンケート → 送信
  6. ターゲットユーザー — 18歳以上 → 保存
  7. ニュース / 政府 / 金融 / ヘルス — すべて該当なし → 保存
  8. ストアの設定 — カテゴリ「ツール」・メール・サイト URL → 保存（RH: partner.reverse-re-birth-hack.com）
📷 RH 実証: 広告 ID — TWA で広告SDKなし → いいえ → 保存。未申告だと送信ボタンが赤エラーで止まる
📷 kimito 実証: 「広告 IDの申告が不完全です」＝赤エラー（黄色警告と違い対処必須）
6
製品版 v7 を審査に送信 人間（最後のボタン）
公開の概要 →「○件の変更を審査に送信」
  1. 製品版 — v7 draft に AAB が載っていることを確認
  2. 国や地域を選択 — 日本（＋必要なら「その他すべての国」）→ 保存
  3. 公開の概要 — 未送信の変更一覧を確認
  4. 「○件の変更を審査に送信」 を押す（RH 実証: 9件）
📷 送信前: 製品版 v7 は下書き・非アクティブ。「一時的なアプリ名 (unreviewed)」も正常
📷 RH 実証: ボタンが青くなった状態（製品版・ストア・申告9項目がまとまって送信待ち）
📷 kimito 実証: 公開の概要の送信ボタン（押すまで審査は始まらない）
📷 確認ダイアログ → 送信
📷 RH 実証: 送信後「審査中の変更」。ここまで来たら人間の作業は完了 → あとは待つ
📷 kimito 実証: 内部テスト送信後も同じ「審査中の変更」画面
✅ RH 実証（2026-06）: 上記9件送信 → クイックチェック → 審査中 まで到達済み。管理対象の公開オフ＝承認後自動公開。
📺 プロモ動画（任意）: YouTube 限定公開 → ストア掲載に https://www.youtube.com/watch?v=jyO9VGHsw2k。 Shorts/TikTok/Reels は審査通過後でも可。
7
（条件付き）クローズドテスト 12人×14日 新規個人アカウントのみ
2023-11-13 以降の個人開発者アカウントで本番アクセス申請が必要な場合
ダッシュボードに「より多くのテスターでアプリをテスト」（1/5 等）が出ていたら:
① クローズドテスト（内部テストはカウントされない）
② テスター 12人以上 が opt-in
③ 連続14日 維持
④ ダッシュボードから 本番環境へのアクセスを申請（アカウント所有者のみ）
→ その後 Step 6 の製品版送信が可能になる。
