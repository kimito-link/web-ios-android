ホーム ＞ 管理体制・API導線

開発プロセス・品質保証の考え方

新しい機能を作るときも直すときも、次の考え方を優先しています。

1. 既にあるものを先に探す

新しく作る前に、社内の他のプロジェクトに同じ仕組みが無いかを必ず確認します。同じ機能をあちこちに複製すると、片方だけ直して片方が古いままになる事故につながるためです。

2. 実際に動かしてから完了と言う

コードを読んで「動くはず」で終わらせず、実際に動かして結果を確認してから完了と報告します。テストが緑でも、実機・実データでの確認は別に行います。

3. 出荷前の自動チェックを必ず通す

アプリをストアに出す前や、コードを本番に反映する前には、機械的なチェック（出荷ゲート）を必ず通します。人の目視だけに頼りません。

4. 数字や実績は根拠とセットで書く

「実績があります」と書くときは、必ずその数字を出したコマンド・ファイル・日付を確認してから書きます。裏付けのない数字は載せません。

5. 認証情報は用途ごとに分けて発行する

外部サービスへの接続に使う鍵（APIトークン）は、1つを使い回さず、機能ごとに必要最小限の権限だけを持つものを分けて発行します。不要になった鍵は無効化し、定期的に棚卸しします。
