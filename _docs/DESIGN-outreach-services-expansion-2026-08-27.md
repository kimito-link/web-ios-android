# 設計: 外販窓口サービスの横展開戦略

> 設計 = Fable（claude-fable-5サブエージェント） / 素材集め = 無料会議ハーネス（5体召集・4体有効回答） /
> 裏取り = 司令塔（Claude、ココナラ・ランサーズで実際にリサーチ・出品操作を実行して確認済み） /
> 日付 = 2026-08-27 / council-fableスキルの3段構え手順2の産物

## この設計に至った経緯

2026-08-27、web-ios-androidキットの既存出品「セキュリティ対策WordPressWebサイトます」を、
ユーザー（りんく）とともに、ココナラ・ランサーズ両方で実際に検索リサーチ（競合タイトル・
人気カテゴリ・タグ・出品件数）した上で「AIで開発したWebサイトの脆弱性診断・お見積りします」に
書き換え、新規バナー画像も作成して両方に公開した（オーナー1人、実装は外部エンジニア
（coreKeiさん等）へ委託する窓口型ビジネスモデル）。

ユーザーから「外に出せるサービスをどんどん頼む、ディープリサーチしてキーワードとか内容も考慮」
という依頼を受け、次にどのプロジェクトから横展開すべきか「会議がいいかと」との指示で
council-fableスキルにかけた。

## 確定した事実（司令塔が実地で確認済み）

- ココナラの出品上限は20件（実際に「サービスの出品可能数をオーバーしています」エラーに遭遇）
- ランサーズのパッケージ上限も20件（「受付中20件」で確認）
- ランサーズ「生成AI・LLMアプリ開発 > セキュリティ対応・診断」カテゴリは登録0件
- ランサーズ「セキュリティ・データ保護」カテゴリは144件の激戦区、人気ランキング3位に
  「AIで開発したWEBアプリの脆弱性診断（セキュリティ診断）を行います」29,000円〜・評価14件が実在
- → 0件のニッチより実需要のある激戦区を選ぶ判断が、実データと整合した

## 優先順位（最終結論）

**① web-health-check.link → ② reply-copilot-openrouter-v2 → ③ soushin-suggest.link（当面凍結）**

- ①は今日公開した脆弱性診断の**独立サービスではなく入口ファネル**として設計する
  （役割分担: 健康診断=軽量・低心理障壁の入口 / 脆弱性診断=3万円〜の本丸。
  共食い防止のため出品文冒頭で両者の違いを明記し相互リンクする）
- ②はカテゴリ圏が変わる（セキュリティ→業務効率化・AI活用）ため実地リサーチをゼロから
  やり直す必要があり、①のSOPが1周検証されてから着手する
- ③は「ニッチ・単価が届きにくい」に加えて、**製品自体に既知の未解決不具合（白化問題、
  soushin-suggest.link/_docs/BLANK-TRUTH.md に記載の10回以上再発・5回の修正が外れた症状）が
  ある**ため、製品が安定するまでは出品しないことを必須条件とする（後回しではなく凍結）

## 横展開の型（SOP・8ステップ）

1. 候補選定（動いている・1行で通じる・委託先が受けられる、の3条件）
2. 実地リサーチ（30〜60分、リサーチログ1枚を残す。**推測でキーワードを決めない**）
3. 書き換え対象の選定（評価0件・実績なしの最弱出品のみ。評価付き出品は書き換えない）
4. タイトル・本文・価格の確定（リサーチログ根拠、最低3万円ライン維持、未検証の実績数値を書かない）
5. フィルタカードの作成（後述D）
6. 公開（ココナラ・ランサーズ両方）
7. 問い合わせ運用（共通テンプレ＋該当フィルタカードの4問目）
8. 2週間後の振り返り（表示・問い合わせ・成約をログに書き戻す）

## 運用リスク対策: フィルタカード方式

会議の指摘（サービス多様化で共通3点ヒアリングだけでは判断材料が不足し、低単価案件を
見逃して受注するリスク）を踏まえ、**テンプレ本体は改造せず、サービス固有部を1枚のカードに
外出しする**:

```
共通3点ヒアリング（不変・全サービス共通） + サービス別フィルタカード（出品1件につき1枚）
```

カードの中身: ①4問目（サービス固有の追加質問1問）②足切り基準（3万円未満になる典型パターン）
③対象外リスト ④委託判断メモ（どこから先が委託先の作業か）

## 次の1件（MVP）

**ランサーズ・ココナラで「サイト 診断」「表示速度 改善」「SEO 診断」等を実際に検索し、
リサーチログ1枚を作る**（所要30〜60分）。出品の書き換えはログ完成後。
想定タイトル案（リサーチ前の仮説、実地確認で必ず上書きする）:
- 「Webサイトの健康診断（表示速度・SSL・SEO・セキュリティ設定）と改善お見積りをします」
- 「AIで作ったWebサイトの総合健康診断（速度・SEO・設定漏れ）をします」（AI文脈の横展開）

## 捨てた案と理由

1. soushin-suggest.linkの早期展開 → 製品の未解決不具合により凍結（上記）
2. reply-copilotの上位概念パッケージ化（「AI Business Infrastructure Audit」等） →
   検索にかからない・実地リサーチ原則と衝突・見積もり不能なため却下
3. ランサーズ0件ニッチカテゴリへの出品 → 需要ゼロの可能性が高いため見送り継続
   （ただし月1回の登録件数チェックだけ低コストで継続）
4. 新規出品の増枠 → 20件上限に実際に衝突済み、書き換え方式が唯一の現実解
5. 複数サービスの同時展開 → 1件目の成約データがない段階での並列展開は型の欠陥を複製する
   リスクがあるため、1サービスずつ順に回す

## 地雷と回避策（全8件）

1. 評価付き出品の書き換え禁止（レビューと内容の食い違い・規約リスク）
2. 健康診断と脆弱性診断の共食い防止（冒頭で役割明記・相互リンク）
3. 会議の「検索データ」主張は未検証として扱う（検証手順だけ拾い、事実として採用しない）
4. 委託先キャパの事前確認を公開前に必須化（受注後の納品不能を防ぐ）
5. 他人所有サイトの診断は法的地雷（不正アクセス禁止法等）→ 出品文・フィルタカード・
   対象外リストの三重で「自己所有サイトに限る」を明記
6. 一括書き換えの誘惑を避ける（1件公開→2週間の指標確認→次、のリズムを守る）
7. 相見積もり圧力での価格崩れ防止（最低3万円は制約として不変）
8. 出品文への未検証実績記載の禁止（出典のない数値は書かない、一般表現に言い換える）
