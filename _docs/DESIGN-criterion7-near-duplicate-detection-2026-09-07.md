## B. 統合アーキ — 結論: 新規ファイル1本（KEEP_SEPARATE）

`templates/diagnostics/check-near-duplicates.mjs` を新設し、`run.mjs`の`CHECKS`に登録する。
`check-shared-parts-used.mjs`は一切触らない。

### 「新規ファイルを作らない」という09-02の判断を覆す理由（4つ）

1. **事実と推測を混ぜない**（Architecture Mapが`fact`/`heuristic`を分けている流儀と同じ）。同名定義の存在は事実。「似た塊」は推測。推測を事実の検査に混ぜると、事実の検査がオオカミ少年になり、本物の赤が埋もれる。
2. **測定の前提条件が違う**。check-shared-parts-usedは`sharedDir`が無いと測れない（正しい設計）。基準⑦検出は共有置き場が無いリポでこそ動く必要がある。1本にすると「sharedDir未宣言＝両方測れない」になり、基準⑦の存在意義が消える。
3. **出力の形が違う**。前者は「関数名→定義箇所」、後者は「ファイルA:行範囲 ≈ ファイルB:行範囲」。無理に同じ`judge`関数に載せると既存selftest 7件と戻り値契約を壊す。
4. **09-02の「新規ファイルを作らない」は同名問題のスコープ内での判断**。今回は問題が別なので、判断を覆すのではなく適用範囲外として扱う。09-02文書は書き換えず、G節末尾に日付つきで「基準⑦検出は別検査として設計（本文書）」と1行追記して決着を記録する（蒸し返し防止）。

### 「G-9: CLAUDE.mdに基準⑦を足さない」と、実際に足してしまった前提のズレ

**基準⑦の文章は削除しない。代わりに「検査済みの規範」にする。**

- G-9の主張は「検査していない規範は守られない＝文章を増やしても解決しない」。この主張が禁じているのは**検査の無い文章**であって、文章そのものではない。基準⑦は「直し方」を増やさず「見分け方」だけを足しており、文章として害は小さい。
- 今、基準⑦は**検査が無い4箇所目の重複禁止文**になっている。解消する手段は文章を消すことではなく、本設計の検査を配線すること。

## C. 具体機構

### C-1. 検出アルゴリズム（依存ゼロ・ASTなし・関数切り出しなし）

09-02が「中括弧カウントで誤判定した実績がある」と記録した関数切り出しを使わない。
単位を「行」にすることで切り出し自体を不要にする。jscpd等の業界標準が採る
「正規化トークン列の連続一致」を、トークン単位ではなく行単位に落としたもの
（自前実装は「標準ツールが使えない領域を埋める先取り」として冒頭コメントに明記し、
jscpdの`min-lines`/`min-tokens`に相当するパラメータ名を踏襲する）。

**手順**
1. 対象ファイルを`git ls-files`から取る（拡張子: `.js .mjs .cjs .jsx .ts .tsx .html`）。除外正規表現はcheck-shared-parts-usedと同じ（`node_modules|vendor|third_party|dist|build|out|_backup|.min.`）。
2. 先頭20行に生成物マーカー（`@generated` / `自動生成` / `DO NOT EDIT` / `generated by`）があるファイルは対象外にし、件数を「生成物として除外 N件」と出す。
3. 各行を正規化する: ブロック/行コメント・HTMLコメント除去 → 文字列リテラルを`S`、数値を`0`、JS予約語以外の識別子を`I`に置換 → 空白圧縮 → `import`/`export ... from`行と正規化後4文字未満の行を落とす → 500文字超の行は落とす（minified対策）。CRLFは事前に除去。
4. 連続k=5行を1窓としてハッシュ（`node:crypto`のsha1で足りる）。ファイルごとに窓ハッシュの順序列を持つ。
5. 転置索引（ハッシュ→[ファイル, 開始行]）を作り、2ファイル以上に出る窓だけを見る。同じファイル対で開始行が連続する窓をつなげて連続一致の塊にし、行数が`MIN_LINES=12`以上の塊だけ採用する。
6. 同じ塊が3ファイル以上にあるものは1クラスタにまとめる。

**定数の根拠**: 短い定型は12行に届かないので数えない。カード部品・描画関数は概ね15〜40行なので届く。定数は配布先ごとに変えない（knobを増やすと「通すために緩める」が起きる）。実測で外れたらキット側の定数を変えて全配布先に効かせる。

### C-2. 判定（純関数・fsに触らない）

- 指標: 12行以上の連続一致の塊の数（塊単位で数える。ファイル対単位ではない）。
- ラチェット: `--baseline N`があれば`count > N`で赤。無ければ緑＋「初回: `--baseline N`として記録してください」。
- `inconclusive`（exit 2）: git ls-filesが実行できない／対象ファイルが2件未満／全件が生成物・除外で落ちた。
- 判定しないこと（出力末尾に毎回出す）: 統合すべきかは言わない／PAIRS宣言済みの意図的複製も数える（意図的複製はbaselineに含めて「増えた分だけ見る」）／構造が違う意味的同一（例: ループ vs `map`）は拾えない／12行未満に割れば数字は下がる（それを咎めない）。

### C-3. 宣言とコマンド

| 目的 | コマンド／場所 |
|---|---|
| 単体実行 | `node templates/diagnostics/check-near-duplicates.mjs [対象dir] [--baseline N]` |
| 毒テスト | `node templates/diagnostics/check-near-duplicates.mjs --selftest` |
| ランナー経由 | `npm run diagnostics`（`run.mjs`の`CHECKS`に`declares: { nearDupBaseline: '--baseline' }`で登録） |
| baseline宣言 | 対象リポの`diagnostics.json`に`"nearDupBaseline": N`（既存の`declares`機構をそのまま使う） |

### C-4. 出力形式

```
[check-near-duplicates] 走査 412 ファイル（生成物として除外 37）/ ★12行以上の似た塊 9 件（上限 9）
  ⚪ 3ファイル × 23行: popup/render.js:40-62 ≈ options/list.js:12-34 ≈ side/panel.js:88-110
  ⚪ 2ファイル × 15行: site/a.html:120-134 ≈ site/b.html:96-110
  （上位10件のみ。ソート: ファイル数→行数）
  → 直し方: 共有置き場（scripts/lib・shared/ 等）へ切り出して両方から呼ぶ。
    ★意図的な複製（配布境界をまたぐ等）なら PAIRS に登録し、baseline を上げて理由をコミットに書く。
  → この検査が判定しないこと: 統合すべきか／構造が違う同目的コードは見ません。
```

### C-5. selftest（毒→赤）に入れる8件

1. 識別子・文字列を変えただけの15行×2ファイル → 塊1件（「名前が違っても拾う」の証明）
2. 同一だが8行 → 0件（閾値未満）
3. コメントだけ同一 → 0件
4. 同じ塊が3ファイル → クラスタ1件・所在3箇所
5. 生成物マーカー付きファイル → 除外され数えない
6. `count > baseline` → fail／`≤` → pass／baseline無し → pass＋提案行
7. ファイル2件未満 → inconclusive
8. null入力でthrowしない

## E. 捨てた案と理由

| 案 | 捨てた理由 |
|---|---|
| jscpdをdevDependencyに入れる | `templates/diagnostics/`は依存ゼロ・対象リポに何もインストールしない規約。配布先の多くはnpm installを前提にしていない。★ただし本検査の精度が実測で足りなければ最初に検討する昇格先。冒頭コメントに「jscpdの行単位縮小版」と明記して乗り換え先を隠さない |
| AST（acorn/babel/tree-sitter）導入 | 09-02で却下済み。行正規化で基準⑦の「コピーして少し変えた」型は拾えるので、覆す強い理由が無い |
| 自前のトークン列Rabin-Karp | 正規表現リテラル・テンプレートリテラルの字句解析を自前で持つと、09-02が記録した「中括弧で狂う」と同種の失敗を字句レベルで再生産する。行単位なら失敗しても「拾えない」側に倒れる |
| check-shared-parts-usedを拡張して載せる | B節4点。特に事実と推測の混在 |
| 関数単位で切り出して比較 | 中括弧カウントの誤判定実績。行窓なら切り出し不要 |
| ファイル名の族検出（1語だけ違う名前） | 基準⑦の例に直接対応し実装も安いが、routes/pages等の正当な並列ファイルを大量に拾う。中身の一致を見る本案に包含される |
| LLMに「似ているか」を聞く | Gateは再現可能・決定的でなければならない。同じ入力で判定が揺れる検査はラチェットにできない |
| 塊が1つでもあれば赤（hard fail） | 「通すためだけの嘘の統合」を誘発する。ラチェット一択 |
| リポ横断走査 | 横断複製はPAIRSの責務。数分かかる走査を配布物に入れない |
| CSSも対象にする | ユーティリティ的な繰り返しが多く、行正規化では意味の違いを区別できない。MVPで入れると偽陽性の主因になる |
| CLAUDE.mdから基準⑦を削除してG-9を守る | 削除は「検査が無い」問題を解かない。公開済み文書の履歴を消すより、検査済み規範に格上げする方が根本解決 |
| `.near-duplicates-baseline.json`（dotfile方式） | 既に`diagnostics.json`の`declares`機構がある。宣言ファイルを増やさない |

## F. 地雷と回避策

1. `run.mjs`はstdoutに`(skip)`があるとskip扱いにする。通常出力にこの文字列を含めない。
2. `templates/diagnostics/`は`../scripts/lib`をimportしない規約。正規化ロジックは自前に持つ（`check-drift.mjs`が同じ判断でcodeOnlyを複製した前例に倣う。実装時にPAIRS登録するか自前実装と書くかを選び、Receiptに記す）。
3. キット自身の`site/hub/`生成HTMLが最大の偽陽性源。生成物マーカー除外が効かないジェネレータがあれば、ジェネレータ側にマーカーを1行足す（検査側に除外パスを足さない）。
4. Windows: `git ls-files`は`/`区切りで返る。CRLFは正規化前に除去しないと窓ハッシュが一致しない。
5. check-selftest-coverage / check-runner-registers-all / check-decision-receipt が同時に赤になる。selftest・登録・Receiptを同じコミットに入れる。
6. 初回baselineは実測してから書く。数字を見ずに`0`と書くと初回から赤（キット自身にも塊はある前提）。
7. 09-02手順2〜4に後で着手する人への注意: `judgeSharedPartsUsed`の戻り値は追加のみ（既存キー・selftest 7件を壊さない）／ラチェット対象を`identical`のみに変えると`.shared-parts-baseline.json`の意味が変わるので再生成して理由をコミットに書く／`extractDefinedFunctions`は触らない／本体切り出し失敗は`unmeasured`。
8. 「見つかった＝統合せよ」と読ませない。出力末尾の「判定しないこと」を省略しない。
9. 12行未満に割って数字を下げる抜け道は塞がない（塞ごうとすると閾値がknob化して腐る）。文書に「そういう抜け道がある」と正直に書く。
10. `site/`を触らないのでdeployは不要。ただしREADME/CLAUDE.md変更はgit pushまで（「コミットした≠反映した」）。
