# Apple 開発者アカウント終了の実数と、このキットの守り方

> **今の到達点: 数字は公式で確認済み・守りは既存の仕組みへの紐付けまで（新しい検査の実装はなし）。**
> 出典（一次）: Apple「2025 App Store Transparency Report」https://www.apple.com/legal/app-store/transparency/2025/ を 2026-10-18 に実読。
> きっかけ: X投稿（@nomalex_）。投稿の数字は公式と一致したが、**投稿の解釈（「復元率5%＝異議申立てはほぼ無意味」）は公式の脚注と食い違う**ので下で直す。
> 関連: 審査の規則 [`docs/ai-rules/01_CORE_RULES.md`](../docs/ai-rules/01_CORE_RULES.md) §5-3、スパム判定への備え [`DESIGN-apple-4-3a-spam-response-2026-10-06.md`](DESIGN-apple-4-3a-spam-response-2026-10-06.md)。

## 公式の数字（2025年・開発者アカウント）
| 項目 | 件数 |
|---|---|
| 登録済み Apple 開発者 | 60,597,750 |
| 終了（terminated）されたアカウント | **193,035**（登録者の約0.32%） |
| うち DPLA 3.2(f)「Fraud（不正）」 | **192,702**（99.8%） |
| うち DPLA 4.8「Export Control」 | 333 |
| 終了への異議申立て | 10,127（終了の約5.2%） |
| 復元（restoration） | **499**（異議申立ての約4.9%／終了全体の約0.26%） |

## 正しい読み方（投稿との違い）
- Apple は脚注で「**異議申立てされる終了の大半は、不正（fraud）が理由で終了されたもの。したがって、そうした申立ての大半は却下される**」と明記している。
  つまり復元が少ないのは「Apple が聞く耳を持たない」より、**申立てた側の多くが本物の不正だったから**。正当な開発者の勝率が5%という意味ではない（公式からは**正当な開発者の復元率は分からない**）。
- それでも**実務の結論は変わらない**: 終了の99.8%は「不正」分類で、終了されると**そのアカウントの全アプリが一緒に止まる**。復元の道は細い。だから**終了されない（「不正」と見なされない）ことに投資する**のが先、異議申立ての技は後。
- 「グレー/ダークパターンで攻める」は、Appleが不正と見なした場合の損失（全アプリ）に対し、得るものが小さすぎる。投稿のこの結論は妥当。

## このキットの守り（既存の仕組みへの紐付け）
1. **「不正」と見なされる形を作らない**: 隠し・休眠・未申告の機能（2.5.19・CHECK 31）、誤解を招くメタデータ（2.3.x）、他アプリの名義の混入、クリエイティブアセットの禁止表現（2.3.14・CHECK 32）。[01_CORE_RULES §5-3](../docs/ai-rules/01_CORE_RULES.md)。
2. **姉妹アプリを似せない**: 同型のアプリを量産すると 4.3(a)（スパム）の対象になる。`verify-team-distinction.mjs` と lint CHECK 24〜30（[設計](DESIGN-apple-4-3a-spam-response-2026-10-06.md)）が、提出前の自己点検。
3. **解約を妨げる・誤解させる圧をかけない**（Retention Messaging の文面なども同じ。[メモ](apple-retention-messaging-api.md)）。
4. **アカウント単位で全部止まる前提で、逃げ道を持つ**: ①ソース・メタデータ・スクショ・審査メモをApple外（git・`store-assets/`）に持つ ②Web側（server.url 型はサーバーに中身がある）と Android を先に自走させる ③顧客への連絡手段をストアに依存させない（LINE・メール）。
   ★どれも**新しい実装ではなく、いまの運用の確認項目**。**実在を確認していない項目は「できている」と言わない**（例: アカウント終了時の連絡手段の切替手順は、このキットに文書が無い＝未整備）。

## 未確認・やっていないこと
- 終了後の異議申立ての**具体的な窓口と手順**（Apple Developer Support の手順）は、この調査では未確認。実際に必要になったとき公式で確認する（推測で手順書を書かない）。
- **同一アカウントのアプリの棚卸しは済み**: ASC に12本（[`apple-account-inventory-2026-10-18.md`](apple-account-inventory-2026-10-18.md)）。アカウントの種別（個人/組織）は ASC API から取れず未確認。
- 投稿が引く「アプリのポートフォリオを見直す」の具体策（どのアプリを残す/止める）は、判断材料（棚卸し）がまだ無いので決めていない。
