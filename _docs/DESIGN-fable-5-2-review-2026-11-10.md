## 1. 結論（先に読む）

1. **Fable 5.2 はこの環境でもう使える。** モデル名 `claude-fable-5-2`。料金は 5.1 より2割安い（100万トークンあたり入力$8・出力$40。5.1 は $10・$50）。
   Claude Code の Agent ツールでは `model: "fable"` で動き、週間上限は「Fable」枠で数えられる。
   Mythos 5.2 は能力・料金とも同じだが、Anthropic の審査を通った組織だけが使える。りんくの環境では Fable 5.2 が対象。

3. **全体設計で一番効く直しは「承認の線を1つの表にすること」。** 今の核は「自分で決めて実行」と「push/マージはOK後」「ロックなしで commit 禁止」と「feature ブランチの commit は並列可」が別々の場所にあり、食い違って読める。

## 3. 承認の表を核へ入れる（2026-11-10 本人OK・実装済み）

今の核の文を変えずに、どれが「確認なしでやってよい」かを名指しする表を「判断の軸」の直後に置く（約12行）。

| 区分 | 操作 | 根拠 |
|---|---|---|
| 確認なしでやってよい | 調べる・読む／作業ブランチでの編集・commit／検査・テストの実行／下書きPRを作る・更新する／自分の作業ブランチへの push | 取り消せる。共有ルール「下書きPR」 |
| 確認なしでやってよい | `templates/`・`.claude/hooks/`・`docs/` の改善（このリポはAIが育てる前提） | 所有者の明示（5.2 の癖への対応） |
| coord を読んでから | `main` を動かす操作（マージ・main への commit/push） | 並列セッション協調プロトコル |
| りんくのOKの一言が要る | PR のマージ／本番デプロイ／secret の設定／課金・契約／外部への送信 | 取り消せない・外向き |

あわせて、核の「coordを読まずにcommit…してはいけない」（L314付近）と「ロックを取らずに git commit」（L348付近）に、
**範囲（main と共有資源への操作だけ。自分の作業ブランチの commit は含まない）** を1語ずつ書き足す。
