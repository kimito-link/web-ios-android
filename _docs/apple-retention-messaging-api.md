## 何ができるか（公式の記述どおり）
解約画面（設定 > Apple アカウント > サブスクリプション、App Store の詳細ページ）で「サブスクリプションをキャンセル」を押した後の
「解約の確認」画面に、**事前に登録したメッセージ**を出せる。種類は4つ:
1. 文章（箇条書き可）／2. 文章＋画像／3. **プラン変更の提案**（より安いプランなど）／4. **プロモーションオファー**（割引で継続）。
- 出せる端末: iOS/iPadOS 15.1 以上・visionOS 1 以上・macOS 14 以上。
- **製品×言語ごとに「既定メッセージ」が要る**。無い組み合わせでは何も出ない。既定は文章（画像・箇条書き可）だけで、オファーは出せない。
- 「誰に何を出すか」を**その場で選ぶ**には、自分のサーバーに Get Retention Message エンドポイントを作る（リアルタイム方式）。

## リアルタイム方式の要件（公式）
- HTTPS・有効なSSL証明書・TLS 1.2。**本番は 700ms 以内に応答**（超えると失敗扱い→既定メッセージ）。
- まずサンドボックスのURLを登録 → **性能テスト（Initiate Performance Test）に合格** → 本番URLを登録。
- 承認済み（APPROVED）のメッセージ・画像だけが表示される。「**誤解を招く・不正確な内容はアップロードしない**」と公式に明記。
- 新ドメイン推奨: api.storekit.apple.com（旧 …itunes.apple.com も当面使える）。

## このキット配下での適用候補（実在を確認したもの）
- **malwarecheck.site**: 監視サブスク（App Store Server Library 利用・通知受け `apps/web/app/api/apple/notifications/route.ts`）。**唯一、サーバー側で Apple と会話する土台がある**＝最有力。
- **resend.kimito-link.com-**（末尾のハイフンまでがフォルダ名）: PHP の `app/services/apple_client.php`。サブスクの有無は未確認。
- 上記以外で自動更新サブスクを出しているアプリは**未確認**（先に台帳で洗う）。

## 進め方（CVR/LTV と100年設計で決めた順序）
1. **アクセス申請（本人）**: 上記ページで申請。AIは代行しない（Apple ID・アカウント操作）。
2. **まず既定メッセージだけ**（サーバー不要・一番安い）: 解約画面に出す「失う機能の思い出し」の文章を、製品×言語ごとに登録。
3. 効果が見えたら**リアルタイム方式**（Cloudflare Workers なら 700ms は余裕。ただし**cold start と Apple への追加問い合わせで超えない設計**にする）。
4. オファー（割引）を出すなら、**そのプロモーションオファーを App Store Connect に先に作る**必要がある（手順は公式「Setting up retention messages」）。
