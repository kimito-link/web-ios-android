# 設計: ココナラ出品枠1件確保 + reply-copilot導入サポート出品

> 設計=Fable（model:"fable"） / 素材集め・裏取り=司令塔（Claude） / 2026-08-27
> council-fableスキル 3段構えの手順2の産物。関連: [[project_outreach-services-expansion-design]]

## 背景・確定事実（司令塔が実地調査・Web検索で裏取り済み）

- ココナラのオーナーアカウント（リバースハック｜サジェスト汚染・逆SEO、ブロンズランク）で
  テキストチャット・データ納品サービスが**ちょうど20件（上限）**に達しており、新規出品しようと
  すると「サービスの出品可能数をオーバーしています」というエラーで出品フォームに進めない。
- 新規出品したいのは「Chatwork・ココナラ・ランサーズのAI返信案を自動生成する導入サポート」
  （reply-copilot-openrouter-v2というChrome拡張機能の実在製品の導入支援窓口）。
  ランサーズ側は既に画像込みで公開済み。
- **ココナラの出品上限は20件、出品者ランク不問**（Web検索で確認）。
- **アーカイブ機能の実際の挙動**（ヘルプセンター記事・複数の二次情報で確認）:
  - アーカイブしても評価・実績はプロフィール・評価一覧・URLから消えない（第三者も閲覧可能）
  - 検索結果・カテゴリ一覧・プロフィールのサービス一覧からは非表示になる（露出のみ失う）
  - 再公開は「アーカイブ一覧」から編集→受付設定を「受付中」に戻すだけで何度でも可能
  - 「出品中のサービスが上限(20件)に達している場合は、アーカイブされたサービスを公開することは
    できません」という記述があり、これは「アーカイブ中は20件カウントから外れる」ことを示唆
    （司令塔の推論、未確定だが根拠あり。設計Dで実操作により確定させる）
- 無料会議ハーネス（3/5成立）の素材: 「プレスリリース記事作成＋サジェスト候補のPR」（評価0件・
  90,000円）をアーカイブ候補とする意見と、「reCAPTCHA」（評価5件、独自ドメイン系と重複）を
  候補とする意見が割れていた。Fableが両者を比較し#8で確定させた（詳細はC参照）。

## 事業制約（変更不可）

- オーナーは「窓口だけ担当・実装は外部エンジニア(coreKeiさん)に高単価委託」というビジネスモデル
  を継続する。運用を複雑にする提案は却下。
- 評価件数が多い出品（69・70・101・109件など）は実績の見え方を優先し、温存したい強い意向。
- 「サービスページの数を増やすこと」自体に価値がある（多くの検索キーワードで露出したいため）。

---

## A. 理想の体験フロー

1. 新サービスの出品文一式（タイトル・キャッチコピー・本文・価格・画像）をランサーズ版から流用し、
   ローカルで完成させておく（ココナラの編集画面を開く前に）
2. ココナラで「プレスリリース記事作成＋サジェスト候補のPR」（#8）をアーカイブ（文面変更はしない）
3. 出品一覧が19件になったか確認
4. 新規出品を作成・画像アップ・保存・公開（有料オプションは今日は付けない）
5. 失敗時はアーカイブ一覧から#8を「受付中」に戻すだけで数分で原状復帰

## B. 統合アーキ（出品ポートフォリオの構成方針）

1. **実績温存の壁（不可侵リスト）**: 評価が1件でも付いている出品は原則動かさない
   （特に評価23件以上の#3,4,9,10,12,14,15,20は完全不可侵）
2. **ゼロ実績枠＝入れ替え自由枠**: 評価0件の出品だけがアーカイブ候補（現在は#8のみ該当）
3. **キーワード網の1分チェック**: アーカイブ前に「この出品で拾っていた検索語は残る19件で
   カバーされるか」を確認する
4. **イベント駆動・無スケジュール運用**: 定期作業はゼロ。「新サービスを出したい」というイベント
   が起きたときだけ①〜③を回して1件動かす

## C. 具体機構

### アーカイブする1件: 「プレスリリース記事作成＋サジェスト候補のPR」(#8, 90,000円, 評価0件)

| 観点 | #8 プレスリリース | #13 reCAPTCHA |
|---|---|---|
| 評価件数 | **0件**（販売実績なし） | 5件（実売あり） |
| テーマ重複 | サジェスト系は#4・#5がカバー | 「#9,10,14と重複」は事実誤認寄り（検索キーワードが実際は別） |
| 検索需要 | 評価0件＝この出品では需要を取れていない実測値 | 5件の評価が需要の実在を証明 |

→ 実売のある#13を消すより、実績ゼロの#8を消す方が実害が小さい。

### 新規出品の具体案

- **タイトル案**: 「ChatworkのAI返信案を自動作成し導入します」（文字数はフォームで実測調整）
- **カテゴリ**: 出品前に「AI 返信」で検索し、上位表示される類似サービスのカテゴリに合わせる
- **価格**: 15,000円（ランサーズと同額）。上振れは有料オプションでなく見積り相談への誘導文で表現

## D. 検証ロジック

事前のサポート問い合わせ等はせず、後戻り可能な実操作で即検証する。

1. アーカイブ前に出品一覧のスクショを1枚保存（20件の証拠）
2. #8をアーカイブ→件数が19件になったか確認
3. 新規作成フォームに進めるか確認
4. 下書きで止めず、実際に「公開」まで通す（ここまで通って初めて確定）
5. シークレットウィンドウで検索結果・プロフィールに新サービスが出るか確認
6. 失敗分岐: ステップ3/4でブロックされたら#8を「受付中」に戻して原状復帰し、次善策を再設計

## E. MVP（今日やることの全リスト）

1. 新サービスの文面・画像をランサーズ版から流用してローカルに完成
2. 出品一覧のスクショ1枚
3. #8をアーカイブ
4. 枠が空いたか確認
5. 新サービスを作成・公開（有料オプションなし）
6. シークレットウィンドウで公開確認

## F. 捨てた案と理由

| 案 | 却下理由 |
|---|---|
| 毎月1件ローテーション | 「窓口だけ・複雑にしない」方針と両立しない。定期タスクは形骸化する |
| #13 reCAPTCHAのアーカイブ | 実売5件のある窓口を消すのは実害。重複認定も誤認寄り |
| 類似出品の統合（#9+#10+#14等） | 評価69〜109件の不可侵出品を編集することになり、既知のフリーズ事故箇所に高価値出品を晒すことになる |
| #8の削除（アーカイブでなく） | 不可逆。アーカイブなら温存でき、需要が実証されたら再公開できる |
| サポートへの事前問い合わせ | 往復数日かかる一方、実験は数分で可逆 |
| 有料オプションで上振れ価格表現 | オプション操作は既知のフリーズ事故箇所。見積り誘導文で代替 |

## G. 地雷と回避策（既知事故: 保存直後フリーズ／有料オプション削除フリーズ）

1. 編集画面の滞在時間を最短化する（文面はローカルで完成させ一括貼り付け）
2. 1ページロードにつき1操作。保存直後の即遷移をしない
3. 有料オプションに今日は一切触らない（新規・既存とも）
4. フリーズしたら再送信しない。別タブで反映確認してから次の行動を決める
5. 操作順は「軽い→重い」（アーカイブ→新規出品）。アーカイブ段階で不調なら中断
6. ココナラのタブは1枚だけ開く（確認用シークレットは別枠）
7. 各操作の直前にスクショを残す
