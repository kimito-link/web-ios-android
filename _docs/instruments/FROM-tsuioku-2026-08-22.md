## 2. ★「上限で切る」は、たいてい「消えた」事故になる

追憶は同じ型を**3回**踏んでいます。

```
v0.1.1052  ①211件 ≠ ③99件
v0.1.1232  ①の上限だけ撤廃し、③は cap 48 に据え置き
v0.1.1234  ★実配信で 238人が会場に載らなかった → cap 撤廃
```

★コミットに、当時の原因がそのまま書いてあります:

> 【原因】司令塔の説明の誤り。「実測で数千人入るので非対称は起きない」と
> 述べたが、★**容量に余裕があっても cap で切る以上は必ず切られる**。
> 容量の話と上限の話を混同していた。

★**これは容量の問題ではなく「切る/切らない」の問題**でした。

### ★付随する地雷: Infinity を渡してはいけない

```
cap に Infinity を渡すと、512KB のフェイルセーフ(cap半減)が
Math.floor(Infinity / 2) = Infinity で【無力化】する。
★上限を外すときは【有限の実測値】を渡すこと。
```

### ⟹ 掟

```
★「多すぎるから減らす」の前に、【減らさずに済む方法】を探す。
★存在を削る解（cap / 仮想化 / 遅延生成）は、
   「後から届く更新」を取りこぼす経路を作りやすい。
★見せ方を変える解（窓・スクロール）なら、存在は消えない。
```
