## 1. ★キットの配布物に穴がありました（最優先）

`templates/scripts/verify-android-signing-config.mjs` の判定が、Groovy のコメントを
剥がさない生正規表現でした。

```groovy
buildTypes {
    release {
        // signingConfig signingConfigs.release   ← コメントアウト（＝未署名 AAB が出る）
    }
}
```

この状態で実行した実測結果（2026-08-24・`--gradle` で毒入りファイルを直接指定）：

```
signingConfig check: OK（署名済み AAB が生成されます）
>>> 終了コード=0
```

★**未署名なのに「署名済み」と断言して緑**。デバッグ中に署名を一時的にコメントアウトする、
というごく普通の編集で門番が素通りします。

もう一段の穴として、スコープ判定が
`src.search(/buildTypes\s*\{/)` から**ファイル末尾まで**を見ていたため、
`debug { }` 側に `signingConfig signingConfigs.release` があるだけでも通りました。

### 直した内容（キット正本に反映済み）

- コメントを剥がしてから判定（技法は `lint-pre-submission.mjs` の `codeOnly()` / `readCapacitorAppId()` から流用）
- ★**波括弧の深さで `release` ブロックだけを切り出す**（同ファイル CHECK 9 の `serverScope` 切り出しから流用）
- 3値化（読めない＝`EXIT.INCONCLUSIVE`）／実測値を出力（従来は OK/NG の字だけ）
- ★`--selftest`（毒→赤）を追加。毒3種＋「正しい入力で緑のまま」の誤検知チェック付き

実測: `exit 0 → exit 1`、正しい入力では `exit 0` のまま（誤検知なし）を確認済み。

★**注意（そちらで直すとき）**: import パスがキットとプロダクトで違います。
キットは `./lib/instrument-core.mjs`、プロダクトは `scripts/app/` 配下なので `../lib/...`。
この1行差のため `check-drift.mjs` の `copies` には入れていません（`copies: []` で正本の存在だけ確認）。
★パスの持ち方を揃えられるなら、揃えて比較対象に入れるのが良いと思います。

## 2. ★「測れなかった→緑」の探し方（`exit 2` の有無では見つからない）

掟②「exit 2 を持っていることと守れていることは別」を、探索手順の形にしました。

このリポの CI 配線済み門番7本を調べたところ、**6本は exit 2 を持っていました**。
それでも実損は起きていました。効いたのは次の数え方です：

```
skip()/warnContinue() 等の【exit 0 を返すヘルパ】の呼び出し箇所
+ if (existsSync(...)) の【else が無い】箇所
+ catch { ... } の中で【exit 0 に落ちる】箇所
```

見つかった実損（すべて CI 配線済み）：

| 門番 | 症状 |
|---|---|
| `verify-splash-bg-consistency` | ★対象3ファイルが1つも無い階層で **「OK（全ての地色が一致）」/ exit 0**。1件も比較していないのに「全て一致」と名乗る |
| `verify-splash-plugin-installed` | `skip()` が exit 0。★自分で「本命」と書いた `packageClassList` 検査を丸ごと飛ばして緑。別の skip は文言に「**判定不能**」と書いた上で exit 0 |
| `verify-ios-splash-not-default` | 参照画像0件でも snapshot が exit 0 で `defaultHashes: []` を書く。★比較集合が空だと後段 `--verify` が**構造的に必ず通る**＝門番の完全な無効化 |
| `lint-pre-submission` | `skip()` が終了コードにも集計にも出ず、★18検査すべてが skip でも「All pre-submission lint checks passed. ストア提出に進んで安全。」。実測でも5件（`uiwebview-scan` / `privacy-manifest` など**実際の却下ベクタ**を含む）が未測定のまま「安全」と表示 |

### ★成功メッセージの言い切りが、症状を隠していました

とくに `verify-splash-bg-consistency` の「**全ての地色が一致**」と
`lint-pre-submission` の「**ストア提出に進んで安全**」は、
★測っていない事実を打ち消す強さで書かれていました。

対策として「緑の言い方」を変えました：

- 未測定が1件でもあれば「全部通った」「提出して安全」とは**言わない**
- 未測定の件数と内訳を**必ず表示**する（見ていないことを見えるようにする）
- ただし**赤にはしない**（この構成では skip の多くは正常。赤にすると常時赤＝オオカミ少年）
- `--strict` のときだけ exit 2（提出直前の CI で「全部測れた」を要求できる）

★掟⑥（一度に全部直せと迫る仕掛けは死ぬ）に沿った形にしたつもりです。

## 3. ★毒テストで私が3回踏み外した型（掟③に足す価値があると思います）

掟③「変異させたと変異が適用されたは別物」は知った上で作業しましたが、**3回踏みました**。
いずれも「赤が出た」または「緑のまま」を誤読しかけています。

### 型1: 固定パスの門番に、別ディレクトリの毒を食わせた

門番が `--gradle` 既定値や `ROOT = スクリプト位置基準` を持つ場合、
別の場所に毒入りファイルを置いても**毒は1文字も届きません**。
そこで出た `exit 1` は「ファイルが無い」という**別理由の赤**でした。

> ★対策: 毒は「その門番が実際に読むパス」に置く。
> あるいは `--gradle <毒のパス>` のように**明示的に食わせる**。

### 型2: 依存の解決エラーを「赤が出た」と読みかけた

`sharp` を top-level import している門番を、依存の無い場所で実行したところ
`ERR_MODULE_NOT_FOUND` で `exit 1`。判定ロジックには**到達していません**。

同じことがキット版の修正直後にも起きました（`../lib` と `./lib` の階層差で
`ERR_MODULE_NOT_FOUND` → `exit 1`）。★**「赤くなった＝直った」と読みかけました。**

> ★対策: 毒テストの前に「毒なしで緑になること（回帰）」を先に確認する。
> 緑が出ないなら、それは検知ではなく**環境の失敗**。
> ついでに selftest 専用ジョブのため、重い依存は**遅延 import** にしました。

### 型3: 台帳の毒を、配列の「順序」を考えずに入れた

退化検知の毒で、①過去の行を**置き換えて**しまい（比較対象が消えて検知不能）、
②次に配列の**先頭**に足しました（過去最良が未確立で検知不能）。
どちらも `exit 0` で、★**2回「検知しない」と誤って結論しかけました**。
正しくは**末尾に追加**で、そこで初めて `exit 1`（過去最良3 @0.1.5 と比較）が出ました。

> ★対策: 「毒が適用されたか」だけでなく
> ★**「毒が判定される位置にあるか」**まで確認する。
> 履歴系の検査では**順序が意味を持つ**ので、`grep` で入ったことを確認しても不十分でした。

## 4. 進化台帳：配布条件を実測で満たしました（＋★落とし穴1件）

規約だけ配布・実装は保留、という判断でしたが、こちらで実装まで通しました。

### 配布条件①：自動記録が走っている

`0.1.5` の3指標を `[auto]` 印付きで記録済み。指標は**実測してから** `better` を宣言しました：

```
selftest-gates         3本   better:'higher'
unmeasured-green-paths 4経路  better:'lower'
inconclusive-gates     6本   better:'higher'
```

### 配布条件②：★サボったときに門番が実際に鳴る

- 記録を全部消す → **exit 2**（fail ではない。規約③どおり）
- `3本 → 1本` の退化を末尾に追加 → **exit 1**（`過去最良 3 @0.1.5` と比較して赤）

★どちらも毒が適用されたことを確認してから読みました（型3で2回失敗した後に）。

### ★落とし穴: `--check` を付けないと鳴りません

```
node scripts/check-improvement.mjs          → 台帳を空にしても exit 0（緑）
node scripts/check-improvement.mjs --check  → exit 2 で鳴る
```

★配線時にフラグを忘れると、**門番を置いたつもりで何も見ていない状態**になります。
これは掟②（持っていることと守れていることは別）の、フラグ版だと思います。
`IMPROVEMENT-RULES.md` の配線例に「★`--check` 必須」と書いておくと事故が減りそうです。

### ★指標の「測り方」自体が弱い印になりかけました

`unmeasured-green-paths` を素朴に `grep -c "process.exit(0)"` で数えたら **5件**。
コメントを剥がして数え直すと **4件**で、★差の1件は**その日に私が書いた解説コメント**でした。

★弱い印で測った数字を台帳に載せると、**間違いを機械で固定**します。
掟①は検査だけでなく、★**指標の測り方にも当てはまる**と思います。
（対策として `count-instruments.mjs` を実コードのみで数える形にし、
「コメントを本物と数えない」ことを selftest で確認しています）

## 5. そのほか、そちらでも起きうるもの

- ★**ワークフローのパスフィルタが実在しないファイルを見ていました。**
  `ios-pre-submission-lint.yml` の `paths` が `capacitor.config.json` 決め打ちで、
  このリポの実体は `capacitor.config.ts`。★Capacitor 設定を編集してもこの lint が
  **一度も起動していませんでした**（門番が門に立っていない）。
  `lint-pre-submission.mjs` 自身も同じ `.json` 決め打ちで CHECK 2 を消滅させた前例があり、
  ★**スクリプトは直したのにワークフロー側の同じ穴が残っていた**という形です。
  → `capacitor.config.*` に変更。そちらのテンプレも確認をおすすめします。

- ★**ステップ名が実装より強い約束をしていました。**
  `Verify reviewer demo account can sign in` という名前でしたが、実装は
  「Clerk に存在し banned/locked でないこと」だけを見ており、★ログインは確かめていません。
  読む人が前提を誤るので、実態に合わせて改名しました（掟の「限界の明記」の名前版）。

- ★**恒久的な無検査が緑で隠れていました。**
  `verify-reviewer-account` は env 未設定を「一時エラー」と同じ exit 0 で扱っていました。
  実際 `CLERK_SECRET_KEY_PROD` は未登録で、開発インスタンスの鍵で本番の審査員垢を
  探していたため、★この門番は恒久的に何も検証しないまま「✓ 確認済み」に見えていました。
  一時エラー（相手都合・再実行で直る）と設定漏れ（こちら都合・直さないと永久に測れない）は
  ★別物として分けるべきだと思います。
