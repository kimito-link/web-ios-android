# 全文脈を把握し、証拠のある学びだけで進化する

> ★「計器の完全版」の入口です。計器を増やす話ではありません。
> 作業前に過去と現在を取りこぼさず、作業後の結果を次回へ戻すための閉ループです。

---

## 0. 先に限界を明記する

AIが文字どおり「世界の全文脈を知る」ことはできません。この仕組みが全件数えるのは、
対象リポジトリから安全に取得できる次の文脈です。

```
① Git追跡ファイルの全件（テキストは索引化、画像等は名前とhash）
② Gitが表示する未追跡ファイル（ignore対象外）の全件
③ ignore対象内の秘密候補（存在だけ。本文もhashも読まない）
④ 未コミット状態・差分の統計・実行できるnpm scripts
⑤ Gitの全コミット件名
⑥ AGENTS.md / CLAUDE.md 等の指示書と、設計・事故・検査の出典
⑦ 数字の進化台帳
⑧ ★確定した判断 / 実測で却下した案 / 未確定の仮説
```

会話にしか残っていない判断、外部サービスの現在値、実機の状態、秘密本文は取得しません。
取得していないものを「正常」や「把握済み」に混ぜないのが、完全版の意味です。

## 1. 1コマンドで全文脈パケットを作る

配布物:

```
templates/scripts/context-engine.mjs
templates/scripts/context-evolution.json
templates/scripts/run-instruments.mjs
```

新しいアプリでは3ファイルを `scripts/` へコピーします。

```bash
# 文脈だけを出典つきの1枚へまとめる（生成物はコミットしない）
node scripts/context-engine.mjs --write .instrument-context.md

# 診断・進化台帳・実行忘れ・selftestまで最後まで測る
node scripts/run-instruments.mjs --deep
```

途中の検査が `exit 2` や `exit 1` でも、統合入口はそこで止まらず、残りをすべて測ります。
最後に `赤 > 測れなかった > 緑` の順で1つの終了コードへ集約します。

---

## 2. 「ファイルを全部貼る」ではなく「全件を計上して出典へ戻る」

全文を1つの巨大ファイルへ複製すると、原文とコピーが必ずズレます。
この計器は、全ファイルを次の形で地図にします。

```
状態 / 分類 / text・binary・sensitive / パス / hash / 見出し・関数の入口
```

説明書の「理由・失敗・実測・却下・限界」に当たる行は、行番号つきで別の索引にも出します。
AIはパケットだけで断定せず、判断するときは必ずそのパスの原文へ戻ります。

★Gitが表示する未追跡ファイルも数えます。作業中の新しいコードが、次のAIから見えなくなるためです。
ただし `.env`、鍵、証明書、`.claude/settings.local.json` は本文もhashも読みません。

---

## 3. 進化は「自動で賢くなる」ではなく、証拠を次回へ戻すこと

`scripts/context-evolution.json` は、数字だけでは残せない判断の台帳です。

```bash
node scripts/context-engine.mjs --record \
  --status confirmed \
  --problem "何が起きたか" \
  --decision "今後どうするか" \
  --evidence "file:src/example.ts:42" \
  --evidence "command:npm test (42 passed)" \
  --outcome "実測した結果"
```

状態は3つだけです。

| 状態 | 次回の扱い |
|---|---|
| `confirmed` | 証拠があり、次回も守る判断 |
| `rejected` | 実測で否定され、もう繰り返さない案 |
| `pending` | まだ仮説。証拠が付くまで知識に昇格しない |

`confirmed` と `rejected` は `evidence` が無いと記録を拒否します。
`file:` は実在を、`commit:` はGitオブジェクトの実在を機械で確認します。
古い判断を変えるときは削除せず `--supersedes <古いid>` を付け、履歴を残します。

## 4. 作業の閉ループ

```
観測  → .instrument-context.md で過去・現在・地雷を読む
判断  → 却下済みの案を避け、原文の証拠から決める
検証  → selftest・診断・実測で結果を確かめる
学習  → confirmed / rejected / pending を証拠つきで台帳へ戻す
  ↑___________________________________________________________|
```

数字は `improvement-history.mjs`、判断の理由は `context-evolution.json` に置きます。
2つを混ぜないため、数字の比較規約（過去最良・方向の宣言）はそのまま保てます。

---

## 5. 自己検査

```bash
node scripts/context-engine.mjs --selftest
node scripts/run-instruments.mjs --selftest
```

固定している事故:

- 追跡ファイルを1件でも数え落とさない
- バイナリを本文として誤読しない
- 秘密候補の本文・hashを採らない
- Gitの全履歴を取得する
- 証拠の無い `confirmed` / `rejected` を拒否する
- 存在しない証拠ファイルを拒否する
- 却下した案を次のパケットにも出す
- 統合時に黄を緑へ丸めず、赤を最優先する

---

## 6. 完了条件

「完全版を入れた」と言えるのは次が全部そろったときです。

1. 文脈パケットに追跡ファイル・Gitが表示する未追跡ファイルが全件計上される
2. 秘密候補を読んでいないことが件数で出る
3. Git全履歴と現在の未コミット状態が同じパケットに出る
4. 証拠つきの判断台帳があり、却下案と未確定案を分ける
5. 自己検査で毒が効く
6. 統合入口が途中で止まらず全計器を測る
7. 機能ページとLPが同じ説明になっている

★パケットを生成しただけでは進化しません。検証後に結果を台帳へ戻して、初めて輪が閉じます。
