## 結論（先に3行）

1. ★**私は「見えない」を「壊れている」と読み違えて、動いていた機能を本番から外した。**
2. 原因は環境の制約（`document.hidden` のタブで `IntersectionObserver` と
   `requestAnimationFrame` が動かない）を知らずに測っていたこと。
3. ★**対照実験を1回やれば最初に分かった。** 所要は10秒。私はそれを3回怠った。

## 1. 何が起きたか（事実）

kimitolink-linktree のLPに「スクロール追体験デモ」がある。
スマホ枠を sticky で固定し、中に**本物の公開ページ**を iframe で埋め込んで、
スクロールすると上から下へ流れる、という部品。

私はこれを復活させ（`8c084cb`）、そのあと**3回**壊した／壊したと誤診した。

### 1回目: iframe が出ない（本物の不具合）

`IntersectionObserver` が発火しない環境で `demoVisible` が false のまま、
「読み込み中…」の空枠が永遠に残った。→ 2.5秒のフォールバックで修正（`1057c45`）。
★**ここまでは正しい仕事。**

### 2回目: ★動いているものを本番から外した（私の誤診）

「②へ進まない」と判定し、**LPの一番上から機能ごと削除した**（`c7cfb5c`）。
だが真実は「**私の計測環境では rAF が動かないので、進捗が更新されないように見えていた**」。

★**利用者の画面では動いていた可能性がある。** それを確かめずに外した。

### 3回目: 切り分けて、ようやく気づいた

対照実験——**画面上に明らかに見えている固定要素**で `IntersectionObserver` と
`requestAnimationFrame` が発火するか——をやったところ:

```
IntersectionObserver : 1.5秒待って ★コールバック0件（仕様上必ず来る初回すら来ない）
requestAnimationFrame: 600pxスクロールさせて ★rafTicks 0 / scrollEvents 0
document.visibilityState: "hidden"
```

★**ブラウザが動いていなかった。デモは（少なくとも一部は）動いていた。**

そのうえで切り分けると、混ざっていた2つが分離できた:

| 症状 | 判定 |
|---|---|
| ②へ進まない | ★**計測環境の制約**。rAFが止まるので原理的に見えない＝**検証不能** |
| iframeが生えない | ★**本物の不具合**（IO非発火時に空枠が残る） |

本物の方だけ直して復活させた（`60d2407`）。

## 2. あなたへの申し送り（これだけ守れば私の失敗は避けられる）

### ★測る前に、測定器を測れ

スクロール連動・遅延ロード・アニメーション・可視判定を検証する前に、**10秒でこれをやる**:

```js
// 明らかに可視な要素で IO/rAF が生きているか先に確かめる
document.visibilityState          // "hidden" なら以降の判定は信用しない
requestAnimationFrame(() => {})   // 発火するか
new IntersectionObserver(...)     // 初回コールバックが来るか
```

来なければ、そこから先に測ったものは**すべて無効**。
★**「動かない」ではなく「測れない」と報告する。** これは敗北宣言ではなく、正しい報告。

### ★「見えない」から「壊れている」へ飛ぶな

私は3回とも、**見えない → 壊れている → 外す**と直行した。
間に入れるべき問いは1つだけ:

> **これは「壊れている」のか、「私に見えていない」だけなのか。**

区別する方法は、たいてい**対照実験**（正常だと分かっているもので同じ測定をする）。

### ★本番から外す前に、影響の非対称性を考える

私が外したのは**LPの一番上**だった。オーナーが「あれ大事だったのに」と言った部品でもある。

- 壊れているものを残す損失: 一部の人に空枠が見える
- ★**動いているものを外す損失: 全員から機能が消える**

**確信が持てないときは、外すより残す方が損失が小さい**場合がある。
最低限、外す前に「私はこれを検証できていない」と申告すること。

## 3. このキットの掟との関係（新しい掟は足しません）

★**これは計器だけの話ではなく、AI自身にも当てはまる。**
自分が何を測れていないかを、報告に書くこと。

## 4. 参考: 同じ日に踏んだ、もう一つの同型

`/kimito` が「見つかりません」と表示されるのを見て、**Tailwind v4移行の回帰を疑った**。

だが `streamerfunch` / `surechigai` は正常だった。
★**CSSが1つのURLだけ壊すことはあり得ない**ので、移行とは無関係と切り分けられた。
真実は「`kimito` というユーザーが存在しない」だけ。

さらに、その確認のために書いた検査自体も間違っていた:

```bash
# ダメな例（正常なページでも必ずヒットする）
curl -s <url> | grep -q "not be found"
```

Next.js は `notFound` コンポーネントを**全ページのRSCペイロードに埋め込む**。
正しい判定は `<title>` を見ること。

★**教訓は同じ**: 測り方が間違っているときも、症状は「壊れている」に見える。
