# 16_VERCEL_BUILD_COST — Vercel は「サイトが変わるときだけ」ビルドする（全プロジェクト共通）

> **今の到達点: 採用（2026-11-24）。CLAUDE.md 核「★★Vercel は要るビルドだけ」の正本。**
> 役割: Vercel にビルドさせるリポは、サイトに関係ない変更（拡張・アプリのコード、docs、dependabot、古いブランチ）でビルドしない。
> なぜ要るか: りんくの依頼（2026-11-24「Vercelのビルド費用を減らす」）。2026-10-20〜11-23 の請求 $99.58 のうち **$77.70（78%）がビルド代**。
> 関連: [07_GROWTH_METRICS.md](07_GROWTH_METRICS.md)（CPA・固定費）／金型 [`templates/vercel/`](../../templates/vercel/README.md)。

## 0. 一言でいうと

**ビルド代は「長さ」ではなく「回数」で決まる。** 1回ごとに分を切り上げ × 4 vCPU（Standard 機械）なので、数秒で終わる静的サイトでも
1回約 $0.014 かかる。だから「ビルドを速くする」より「要らないビルドを起こさない」が効く。

## 2. 決まり

1. Vercel に Git 連携でビルドさせるリポは、`vercel.json` に `ignoreCommand` を入れ、共通の
   [`vercel-ignore-build.mjs`](../../templates/vercel/vercel-ignore-build.mjs) を呼ぶ（入れ方は金型の README）。
2. 拡張・アプリ・サーバーと同居しているサイトは、**サイトに効くパスを引数で渡す**。サイトのファイルが変わらない変更は、本番もプレビューも作らない。
3. 1つのリポ・1つのブランチを、2つ以上の Vercel プロジェクトにつながない。同じ中身を2回ビルドするだけになる。
   ドメインを持たない方のプロジェクトは Git 連携を外す（消さない。戻せる）。
4. 本番はいつも作る。ただし見張るパスが1つも変わっていない本番は省いてよい（前の本番がそのまま残る）。
5. 判断に迷う（前回の SHA が無い等）ときはビルドする。省きすぎて本番が古いままになる損の方が大きい。
6. 新しく Vercel のプロジェクトを作ったら、その日に 1〜3 を満たす。

## 3. 止める・知らせる仕組み

| いつ | 何が | 何をする |
|---|---|---|
| 各リポの点検 | `templates/diagnostics/check-vercel-build-skip.mjs`（`diagnostics/run.mjs` から） | git 追跡の `vercel.json` に `ignoreCommand`（か `git.deploymentEnabled:false`）が無ければ赤。呼ぶスクリプトが無くても赤 |
| ビルドのたび | `vercel-ignore-build.mjs` | 省いた理由をビルドログに1行出す（`[vercel-ignore-build] SKIP: …`） |
| 月1 | AI が Vercel の請求（`/v1/billing/charges`）をプロジェクト別に集計 | ビルド代の上位が変わっていたら、そのリポの見張るパスを見直す |

- **判定しないこと**: ダッシュボード側の設定、見張るパスが正しいか（狭すぎると本番が更新されない）。パスを決めたら、
  サイトのファイルを1つ変えた PR でプレビューが作られることを一度確かめる。
