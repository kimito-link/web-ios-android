# 05 画面を人に渡すときの作法（迷子にさせない）

> 出典: 2026-09-11、LINE公式アカウント作成（`ai-shain-worker/scripts/open-line-form.mjs`）で確立。
> ユーザー指摘:「いつもそういうふうにいわれるけど、**画面をたちあげてもらわないと探すのに迷子でわからない**。
> とまってるってたくさん窓ひらいてるのに」。
> この日は実際に**ウィンドウが最小化（X=-32000）されていて、どのモニタにも存在しなかった**。
> それを「開いたはずです」と案内していた。

## 一言でいうと

**「開きました」と言うな。「見えているか」を機械で確かめてから渡せ。**

AIが自動化を途中で人へ渡す場面（画像認証・ログイン・決済・本人確認）は必ず来る。
そこで人が画面を探す羽目になると、自動化で浮かせた時間が全部消える。
★**渡す瞬間がいちばん事故る。** 作るのは機械、渡すのは人、という境界の設計そのもの。

---

## 1. 「起動した」は状態ではない。座標で確かめる

プロセスが生きていることと、**人の目に見えていること**は別。

```powershell
# ウィンドウの実座標を取る（Windows）
GetWindowRect(hwnd) -> X, Y, W, H
```

★**X が -32000 なら最小化**されている（Windows の仕様）。どのモニタにも映っていない。
プロセス一覧に出ていても、タスクバーにアイコンがあっても、**人には見えていない**。

| 見るもの | 判定 |
|---|---|
| プロセスが存在する | ❌ 足りない |
| `MainWindowTitle` が空でない | ❌ 足りない |
| **X,Y が画面内にある** | ✅ これで初めて「見えている」 |

## 2. ★位置は起動時に渡す。後から直さない

最小化された窓を `ShowWindow(SW_RESTORE)` で復元しても、**即座に最小化へ戻ることがある**
（2026-09-11 実測。復元→400ms後に再取得したら X=-32000 に戻っていた）。

後追いで直すのは競合になる。**起動時に位置を指定する**のが唯一確実:

```js
// Playwright の例
chromium.launch({
  headless: false,
  args: ['--window-position=80,50', '--window-size=1400,950'],
});
```

★この1行があるかないかで、「見つからない」が起きるかどうかが決まる。

## 3. 渡す窓は「勝手に閉じない」ようにする

人が操作している最中にプロセスが死ぬと、作業が消えて最初からになる。

- ★**タイムアウトを付けない**（`timeout 100 node open-form.mjs` は100秒で閉じる。実際にやって消えた）
- バックグラウンドで起動し、**人が終わるまで開いたまま**にする
- 「終わったら Ctrl+C」と明示する

## 4. 場所を言葉で伝える（モニタが複数あるなら特に）

モニタが6枚ある環境では「開きました」は情報がゼロ。渡すときに必ず言う:

```
左上（X=80, Y=50）に 1400x950 のウィンドウ
タイトル: "... - Google Chrome for Testing"
★普段のChromeとは別のウィンドウです
```

★**普段使っているアプリと同じ見た目の別インスタンス**（Chrome for Testing 等）は特に紛れる。
「別物である」と先に言う。

## 5. 人にやらせることを3つ以内に絞る

渡した先で迷わせない。**残りの操作を番号付きで、3つ以内**に:

```
1. 画像認証を解く
2. 「確認」を押す
3. 「完了」を押す
```

入力欄は機械が全部埋めておく。人に埋めさせるのは「機械にできないもの」だけ。

## 6. ★機械が代われない操作を見分ける

以下は**AIが代行してはいけない**。渡すのが正しい:

| 操作 | 理由 |
|---|---|
| 画像認証（reCAPTCHA） | bot検知の回避そのもの。規約違反 |
| ログイン・パスワード入力 | 認証情報の代行 |
| 本人確認・SMS認証 | 同上 |
| アカウントの新規作成 | 本人の名義で規約に同意することになる |
| 決済の確定 | 金銭の移動 |

★ただし**「その手前まで」は機械がやる**。フォームの入力・画面の到達・位置合わせを
全部済ませてから渡せば、人の手数は最小になる。
「できません」で丸投げするのと、「ここまでやったので残り3クリックです」は別物。

## 7. 完了を人の言葉で判定しない

「できました」を鵜呑みにしない。★**機械が読める完了条件**を先に決めておく:

```
URL が /complete を含む        → 成功
URL が /confirmation のまま    → ★失敗（画像認証で止まっている）
```

2026-09-08 の実障害: 「完了」ボタンを押したことを `account created` とログに出していたが、
reCAPTCHA で止まっていて**実際には作成されていなかった**。テストは緑のまま。
人がスクリーンショットを開くまで誰も気づけなかった。
