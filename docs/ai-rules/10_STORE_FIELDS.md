## 0. 一言でいうと

**ストアの欄は「必須かどうか」ではなく「商品ページの見え方に効くかどうか」で埋める。** 任意の欄も、効くなら AI が素材を作って入れる。
欄の一覧は表（[`templates/scripts/lib/store-fields.json`](../../templates/scripts/lib/store-fields.json)）が正本。表に無い欄を画面で見つけたら、表に足すところまでが作業。

## 1. 決まり

1. **提出・更新の前に `node scripts/check-store-fields.mjs` を走らせる。** 空いている欄が出たら、その場で素材を作って埋める（人に聞かない）。
   - 必須（✗）… 埋めないと提出できない。
   - CVR（!）… 任意だが見え方に効く。**言われなくても埋める。** 例: ヘッダと検索結果・iPhone Duo のスクショ・App プレビュー・
     プロモーション用テキスト・Play の動画・CWS のプロモーション タイル。
   - 条件つき（·）… その機能・端末に対応するとき、催しがあるとき、だけ。条件に当たるなら埋める。
2. **素材の作り方は表の `make` に従う。** ヘッダ・検索結果・CWS のタイルは `node scripts/generate-store-assets.mjs --creative` が
   アイコン・アプリ名・短い説明から寸法どおり（透明なし）に作る。キャラ・実際の画面を入れた作り込み版は
   `store-assets/creative-assets/header.html` などを置けばそれを撮って使う。既にある絵は上書きしない（作り直すなら `--force`）。
3. **API で入る欄は提出スクリプトが入れる。API に無い欄（表の `fill: "screen"`）は AI が画面で上げる。**
   ASC の「ヘッダと検索結果」・iPhone Duo のスクショ（2026-11-09 時点の ASC API 4.6 に無い）、CWS の画像・説明が当たる。
   AI 用の専用プロフィールのブラウザで開いて上げる（人の普段の Chrome には繋がない）。上げた後は画面を撮って確かめる。
   ★ASC のヘッダと検索結果は **版が編集できる間（提出前）しか上げられない**。提出スクリプトの前に上げる。
4. **画像の中身は目で確かめる。** 機械は文字を読めない。価格・割引・「No.1」などの検証できない主張・他アプリの名前が無いか、
   全年齢向けかを、出来た画像を開いて見る（App Store 2.3.14）。
5. **画面で表に無い欄を見つけたら、表に足す。** 「新しい」「NEW」「アプリの新たなマーケティング手法」などの案内が出ていたら必ず開いて見る。
   `store-fields.json` の `stores` に欄（置き場・作り方・`level`）を足し、テスト（`lib/store-fields.test.mjs`）を通してから素材を作る。

## 2. ストア側で欄が増えたら（見張り）

`node templates/scripts/watch-store-fields.mjs` が、公式の項目一覧を取りに行って表の `watch.*.known` と比べる。

| 見る源 | 何で気づくか |
|---|---|
| App Store Connect API の定義（OpenAPI） | 掲載文の欄・スクショ/プレビューの端末の種類・ヘッダ/検索結果/プロダクトページ系の資源が増えた |
| Google Play Developer API の定義（discovery） | 掲載の欄・画像の種類が増えた |
| Apple のスクショ・プレビュー・クリエイティブ素材の仕様ページ | 見出し・表・端末の区切り（例: `iPhone Duo`）が増えた（API より先にページに出る） |
| Google Play のプレビュー素材のページ・Chrome ウェブストアの画像のページ | 見出し・表が増えた |

- このリポの `.github/workflows/store-fields-watch.yml` が週1で走り、変化があれば Issue（ラベル `ai-task`）を立てる。
- 変化を見たら: 表の `stores` に欄を足す（不要な変化なら足さない）→ `--update` で `known` を今の一覧に揃える → 下書き PR。
- ★見張りが拾うのは「一覧の名前が変わった」まで。寸法の数字だけが変わった等は拾えないので、素材を作る前に仕様ページの寸法も見る。

## 3. 判定しないこと（機械の限界）

- ストアの画面に**実際に上がっているか**は見ない（リポに素材があるかまで）。上げた後に画面で確かめる。
- 素材の**出来の良さ**・言葉の良し悪しは見ない。CVR の比べ方は、閲覧が数百/日を超えたら「プロダクトページの最適化（A/B）」で測る（07 の物差し）。
- 本番の鍵が要る提出・審査への提出そのものは、これまでどおり本人の OK の後。
