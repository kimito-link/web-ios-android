# 14_TRADEMARK_CHECK — 名前を決めたら、ストアに出す前に商標を調べる（全プロジェクト共通）

> **今の到達点: 採用（2026-11-21）。CLAUDE.md 冒頭「★★名前を決めたら商標を調べる」の正本。**
> 役割: アプリ・Chrome 拡張・Web サービスの名前（改名を含む）を決めたら、**ストアの提出・公開の前に** J-PlatPat で
> 同じ名前・似た名前の商標がないかを AI が調べ、結果をリポに記録する。かぶったら名前を変える。
> なぜ要るか: りんくの指示（2026-11-21「これも全体設定に」）。きっかけは X の投稿「アプリ名を決めるとき商標まで確認しているか」への返信で、
> App Store も Google Play も商標侵害の申し立て窓口を持っていて、申し立てが通るとアプリが消される／名前の変更を求められる、という指摘。
> 名前はアイコン・ドメイン・LP・SNS・審査済みの掲載文に染みこむので、**公開後に変えるほど高くつく**（CPA・積み上げた評価・検索順位を捨てる）。
> 実際に「サジェスト汚染チェッカー」は商標が通らず、代わりの名前を考え直した（`_docs/MAP-github-root-cleanup-2026-09-08.md`）。
> 関連: [07_GROWTH_METRICS.md](07_GROWTH_METRICS.md)（名前の変更は LTV÷CPA を下げる）／[10_STORE_FIELDS.md](10_STORE_FIELDS.md)（提出前の点検）／
> [08_NO_HUMAN_HANDS.md](08_NO_HUMAN_HANDS.md)（検索は AI が自分のブラウザでやる）。

## 0. 一言でいうと

**名前は「空いているドメイン」ではなく「空いている商標」で決める。** 第9類（アプリ・ソフト）と第42類（Web サービス・SaaS）を必ず、
宣伝・物販の色が強いものは第35類も、J-PlatPat で同じ・似た名前を調べ、`store-assets/trademark-check.json` に残す。
記録が無い・かぶっているのに出そうとすると、提出前の点検（`lint-pre-submission` CHECK 36・`check-trademark.mjs`）が止める。

## 1. いつやるか

| とき | やること |
|---|---|
| 名前の候補を出すとき | 候補ごとに先に調べる。かぶる候補は捨てる（候補の段階なら何も失わない） |
| 名前を決めたとき（ドメイン購入・ロゴ・LP より前） | 本調査をして記録を作る |
| 改名するとき | 新しい名前で調べ直す（記録の `name` を新しい名前にする） |
| ストア提出・大きな更新の前 | 点検が記録を見る。180日より古い記録は調べ直す（他人の出願は毎日増える） |

## 2. 調べ方（AI が自分でやる）

1. **場所**: 特許庁の無料データベース **J-PlatPat の商標検索** <https://www.j-platpat.inpit.go.jp/t0100>。
   ★クラウドのコンテナや見出しなしブラウザ（headless）からは `reject_sorry.html` に飛ばされて使えない（2026-11-21 実測）。
   **りんくの PC の Claude 内蔵ブラウザ（`Claude_Browser`）** で開く。内蔵ブラウザなら検索まで通る（同日実測）。
2. **入れる語**（スペース区切りは OR 検索）:
   - 「商標(検索用)」… 名前そのもの（表記ゆれも並べる。例: `キミトリンク kimitolink きみとりんく`）
   - 「称呼(類似検索)」… 読みをカタカナで。**似た読みも拾うのはこちら**。読みが違えば別物、ではない
   - 名前が「一般語＋一般語」のときは、目立つ方の語だけでも調べる（「〇〇チェッカー」の〇〇など）
3. **区分で絞る**: 結果の「区分別」で **09・42**（必要なら **35**）を見る。アプリはふつう 9 と 42、両方に当たる。
4. **読み方**: ステータスが「存続」「出願中」のものが対象。「消滅」「拒絶」は基本的に気にしなくてよい（記録には残す）。
5. **ほかに見るもの**（短く）: 同じ名前のアプリが App Store・Google Play・Chrome ウェブストアに無いか／海外でも出すなら
   WIPO Global Brand Database <https://branddb.wipo.int/>。
6. ★**J-PlatPat はロボットアクセス（プログラムによる定期的な自動収集）と大量ダウンロードを禁止している**（J-PlatPat「利用上のご案内」）。
   検索スクリプトや定期的な見張りは作らない。人が1回ずつ検索するのと同じ使い方（1つの名前につき数回の検索）で、内蔵ブラウザから調べる。
   定期的に見張る必要が出たら、特許庁の正式な **特許情報取得API**（無料・利用登録が要る）を使う案を出す。

## 3. 結果の判定と、かぶったとき

| 判定 (`verdict`) | 中身 | 次の一手 |
|---|---|---|
| `clear` | 9・42（35）に同じ・似た名前の存続中／出願中の商標が無い | そのまま進める |
| `own` | 同じ名前の商標を自社（株式会社ベストトラスト）が持っている | 進める。足りない区分があれば出願を**提案**する |
| `renamed` | かぶりが見つかったので名前を変え、新しい名前で調べ直した | 新しい名前の記録で進める |
| `conflict` | 他人の同じ・似た名前があり、まだ変えていない | **出せない**。名前を変える（§3の決まり） |

- **かぶったら名前を変える。** 「区分が少し違う」「読みが少し違う」で押し切らない。似ているかの判断は審査官と相手次第で、
  負けたときの損（名前の作り直し・公開後の削除）が、候補を変える手間よりずっと大きい（判断の軸1）。迷う近さなら変える。
- **一般的な言葉の組み合わせ**（「家計簿アプリ」「タスク管理」など）は、商標の登録自体が通りにくい（識別力が無い）。
  他人に取られにくい代わりに、自分も守れない。守りたい名前なら、造語や組み合わせの工夫を足す。記録の `notes` にそう書く。
- **人に聞かずに決める。** 候補の入れ替え・判定・記録は AI が判断の軸で決めて、あとで報告する（CLAUDE.md「確認なしでやってよいこと」）。
- **専門家に聞きたいとき**は、各都道府県の **知財総合支援窓口**（INPIT、相談無料）<https://chizai-portal.inpit.go.jp/> を案内する。
  電話・訪問は りんくが行うので、聞くことを短く下書きして渡す。

## 4. 出願は「提案」まで（お金がかかる）

商標の出願は特許庁の手数料（1区分ごと）や弁理士費用がかかる＝**りんくの OK が要る操作**（CLAUDE.md の表の最下段）。
AI がやるのは提案まで: 「どの名前を・どの区分で・なぜ今か（公開前に出すと先に取られる危険が減る）」を記録の `filingProposal` と報告に1〜3行で書く。
費用は特許庁の公式ページ <https://www.jpo.go.jp/system/process/tesuryo/hyou.html> を見て数字を添える（記憶で書かない。
2026-11-21 時点の出願料は「3,400円＋区分数×8,600円」、登録が決まるとさらに登録料が要る）。

## 5. 記録の形（`store-assets/trademark-check.json`）

`node scripts/check-trademark.mjs --init` で雛形ができる（名前は `app.config.json` の `identity.displayName` から入る）。

```json
{
  "name": "動員ちゃれんじ",
  "readings": ["ドウインチャレンジ"],
  "checkedAt": "2026-11-21",
  "checkedBy": "claude (J-PlatPat via Claude_Browser)",
  "classes": [9, 42, 35],
  "searches": [
    { "db": "J-PlatPat", "field": "商標(検索用)", "query": "動員ちゃれんじ", "hits": 1 },
    { "db": "J-PlatPat", "field": "称呼(類似検索)", "query": "ドウインチャレンジ", "hits": 1 }
  ],
  "similar": [
    { "mark": "動員ちゃれんじ", "number": "登録7073392", "classes": [9], "owner": "株式会社ベストトラスト", "status": "存続" }
  ],
  "verdict": "own",
  "notes": "第42類は未出願",
  "filingProposal": "第42類（Web サービス）での出願を提案（りんくの OK 待ち）"
}
```

## 6. 機械が見ること・見ないこと

- `templates/scripts/check-trademark.mjs`（と `lint-pre-submission` の CHECK 36）が見るのは、
  ①記録があるか ②記録の名前がいまの `identity.displayName` と同じか（改名したのに古い名前の記録のままを止める）
  ③9 と 42 を調べたか ④`verdict` が `conflict` でないか ⑤180日より古くないか（古ければ警告）、まで。
- **似ているかどうかの判断、検索をちゃんとやったか、は見ない。** そこは AI が §2 の手順どおりにやる。記録の `searches` に
  実際に入れた語と件数を書くのは、次の AI が同じ検索をやり直さずに済むようにするため。
- 商標の確認は法律の助言ではない。争いになりそう・高額な投資の前などは、§3の知財総合支援窓口や弁理士に確かめる。
