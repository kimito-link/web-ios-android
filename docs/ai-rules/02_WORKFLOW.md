# 02_WORKFLOW

## 標準フロー

1. 要件定義
2. 実装（TDD推奨）
3. レビュー
4. デプロイ前チェック
5. デプロイ
6. デプロイ後検証

## 1) 要件定義

- 仕様、完了条件、非機能要件を先に固定
- URL方針（`/price/` 形式、`index.html` 非表示）を先に合意
- レスポンシブの対象画面と検証端末を明記

## 2) 実装

- Red → Green → Refactor の順で進める
- 新規追加した部品は `COMPONENT_REGISTRY.md` へ記録
- 共通ルールに反する実装はこの時点で修正

## 3) レビュー

- 実装者と異なる視点でレビューする
- 表面的な修正でなく再発防止を確認する
- `03_REVIEW_CHECKLIST.md` を使い機械的に抜け漏れを防ぐ

## 4) デプロイ前チェック

- テスト、セキュリティ、依存関係同期を確認
- URL正規化の設定（www統一、http→https）が有効か確認
- 本番で不要なログ/デバッグ設定が残っていないか確認

## 5) デプロイ

- 小さな変更単位でコミットし履歴を明確化
- 失敗時ロールバック手順を事前に確認

## 6) デプロイ後検証

- 主要URLが表示されること
- リダイレクトが意図どおりであること
- モバイル/PCでUI崩れがないこと
