## 0. 一言でいうと

**人の手は「最後の手段」ではなく「設計の失敗」として数える。** 人に頼む前に、AI が自分でやる道を全部ためす。
どうしても残るものは「**年1回以下・1タップ・画面だけで次が分かる**」まで小さくしてから渡す。

## 1. 外さない安全の決まり（この範囲の中で手を減らす）

手を減らすために、次の決まりは**ゆるめない**。ゆるめて手を減らすのは「無人化」ではなく「安全を削った」だけ。

| 決まり | 正本 |
|---|---|
| 本番の鍵を AI が勝手に作らない・発行しない（各社の画面での「発行」は本人） | CLAUDE.md「秘密は『発行』と『取り出し』を混同しない」 |
| AI は人の普段の Chrome に繋がない（専用プロフィールを使う） | CLAUDE.md「AIは人の普段の Chrome に繋がない」 |
| push・PR マージ・本番デプロイ・ストア提出・課金・外部への投稿は、本人の OK の後 | CLAUDE.md「外向き・取り消せない操作」／`guard-external-actions` hook |
| 秘密の値を会話・ファイル・ログに残さない | `~/.claude/CLAUDE.md`「クリップボード経由」 |

★「OK をもらう」は手作業ではない。**OK は一言、作業は AI** に分ける（「マージしていい？」に「いいよ」と返すだけで済む形）。

## 2. 人に頼む前に通す順番（上から順に。当たったらそこで AI がやる）

1. **もう保管されていないか** — 鍵・設定値・ログ・状態は、たいてい既にどこか（Secrets・DB・KV・環境変数・ファイル）にある。
   取り出すだけなら AI がやる（「発行」と「取り出し」は別物）。
2. **公式の API・CLI・MCP で書き込みまで通るか** — 「MCP がある」で止めず、その操作を**実際に1回叩いて**確かめる。
   登録簿や説明ページの一覧は簡略版のことがある。接続して実際のツール一覧を見る。
3. **一度だけの許可で、以後ずっと AI が回せる形にできるか** — 長く使えるトークン（期限は無期限か最長）・OAuth を1回・
   GitHub Secrets に置いて workflow の中で使う（値を誰の目にも出さない）・Remote Control でその PC 上で動かす。
   ★毎回のログイン承認（`vercel login` 等）が要る作りは、トークン方式か MCP に置き換える。
   ★★**PC で走らせるコマンドは、AI が Remote Control で自分で走らせる**（2026-11-10）。クラウドのプロジェクトスレッドは
   `start_remote_control`（承認済みフォルダ・既定の PC）で git pull・npm・`wrangler deploy`・拡張の入れ替えをその PC 上で実行できる。
   初回だけ PC 側に承認の画面が出るが、それは「一度だけの許可」。毎回「Git Bash に貼って」と頼むのは、この段を飛ばしている。
   `wrangler login` のようなブラウザでの本人ログインだけは残る→長期の API トークン（`CLOUDFLARE_API_TOKEN`）に置き換えて年1回以下へ。
4. **AI が自分で見て・読んで・続けられるか** — 画面は AI が自分で見る（ウェブは専用プロフィールのブラウザ、PC のアプリは
   [`agent-desktop`](../ai-workflows/AGENT-DESKTOP-HOWTO.md)、それで読めないものだけ computer-use）。
   黒い画面の中身は、スクリプトが**状態ファイルに書き**、AI がフォルダ接続で読む。人に「いちばん下の行を送って」と頼まない。
5. **自分で直る・自分で入れ替わる形にできるか** — 拡張は [`templates/extension-self-update/`](../../templates/extension-self-update/README.md)、
   無料 DB の休止は定期の起こし役（cron / workflow）、期限切れは期限の前に CI が知らせて自動で差し替え。
6. **ここまで全部だめなときだけ、本人に頼む** — 頼むのは §3 の形にしたものだけ。頼んだ理由（どの順番でだめだったか）を一行添える。

★否定（「これは AI にはできません」）を言う前ほど、この順番を飛ばしやすい（CLAUDE.md「否定形で答える前ほど検索を飛ばしやすい」）。

## 3. それでも残る手作業の合格基準（3つ全部満たしてから渡す）

| 基準 | 合格の形 | 不合格の例 |
|---|---|---|
| **年1回以下** | 一度やれば以後は AI が回せる。期限のある鍵は最長・無期限で作ってもらう | 30日で切れる鍵を作らせる／デプロイのたびにログイン承認 |
| **1タップ** | 開くべきページの**直リンク**を出し、押すのは1つ（多くても3つ・番号つき）。コピーした値は黒い画面ではなく受け取り役が自動で拾う | 「メニュー→設定→API キー」と階層で説明／Enter を2回／貼り付けを頼む |
| **画面だけで次が分かる** | 渡す画面・スクリプトの表示だけで、次に押すものが分かる（01 §3-1 と同じ物差し）。終わったら勝手に次へ進む | 「終わったら一言ください」「黒い画面の様子を教えて」 |

本人しか押せないものの例（2026-10-28 時点。各社の決まりが変われば見直す）:
- 本番の鍵の**発行**ボタン（LINE チャネルシークレット・X・Clerk のシークレットキー・Anthropic Console の API キー）
- 課金・支払い方法・上限金額の変更、規約への同意、本人確認・画像認証
- 不可逆・外向きの操作への **OK の一言**

## 3.5 Web 画面でしか通らない操作は、りんくの Chrome にいる Claude へ「貼るだけの文」で渡す（2026-11-10 本人指示）

> りんくの言葉:「このやり方をキットにも伝えて全体設計のルールにいれて」（Kimito Link Voice の iOS／Android 初回申請）

**どんなときに使うか**: §2 の 1〜5 を実際に試してもだめで、りんくがログインしている画面でしか通らない操作が残ったとき。
2026-11-10 に当たったのは次の2つ（どちらも API では通らないことを CI のログで確かめた）。

| 操作 | API で通らない証拠 | 開くページ |
|---|---|---|
| App Store Connect「アプリのプライバシー」の回答と公開 | 提出が `409 STATE_ERROR.APP_DATA_USAGES_REQUIRED`。`dataUsages` は Web セッション専用で、API キーでは 404／401 | `https://appstoreconnect.apple.com/apps/<appId>` |
| Google Play Console の新しいアプリの作成と、サービスアカウントへの権限付け | Play API が `Package not found: <applicationId>`（アプリの作成は API に無い） | `https://play.google.com/console` |

**やり方**: クラウドのスレッドからは、りんくの普段の Chrome を動かせない（§1 の決まりでも繋がない）。
りんくの Chrome には Claude（サイドパネル）がいて、りんくのログイン状態のまま画面を操作できる。
だから「手順の説明」ではなく、**その Claude にそのまま貼る文**を渡す。りんくの手は「貼る」と「OK の一言」だけになる。

貼る文に必ず入れるもの:

1. **直接開ける URL**（メニューの階層で説明しない）。
2. **入力する値を全部**。値は正本から取る（`app.config.json` の `identity`、`store-assets/REVIEW-NOTES.md` の申告メモなど）。
   その場で考えた値を書かない。
3. **あとで変えられない値は、名指しで書く**。Android のパッケージ名は `applicationId` と一字一句同じにする（作成後は変更できない）。
4. **最後のボタンを押す前に、入力内容を見せて確認を取る**、という一行（作成・公開・送信の前）。
   確認を取るのは「あとで取り消せないボタン」だけ。途中の保存では聞かせない（下の 7）。
5. **規約への同意のチェックは、りんくに聞く**、という一行。同意は本人のもので、AI が代わりに決めない。
6. 終わったあと続けてやること（例: 作成のあとサービスアカウントに権限を付ける）。
7. **答えは最初に全部渡し、止まる条件だけを書く**（2026-11-10 追記）。画面に並ぶ項目を先に全部数え、
   1つの文に全項目の答えを入れる。そのうえで次の3行を必ず入れる。
   - 「1項目ずつ確認を取らずに、下の答えで保存まで進めてください」
   - 「ほかに出てきた項目は『該当なし／いいえ／使用していない』に当たる選択肢で保存」（そのアプリで本当にそう言える場合だけ）
   - 「止まって見せるのは、規約への同意・費用が発生する画面・上の答えに当てはまらず後から変えられない項目・最後の送信ボタンだけ」
   ★実例（2026-11-10）: Play Console「アプリのコンテンツ」（プライバシー ポリシー、広告、レーティング、ターゲット ユーザー、
   広告 ID、行政、金融、健康、取引業者ステータス、カテゴリ、国と地域）を、項目の名前だけ渡して始めた。
   Chrome の Claude は項目ごとに3〜4択を出し、りんくはそのたびにスクリーンショットを撮ってスレッドに貼り、返事を貼り戻した。
   りんくの言葉:「選択肢がおおい　kitだったらいっきにできたはずだけど」。答えを全部入れた文を1回貼る形に直した。
8. **ログインが要る機能があるアプリは、審査用の入り口を先に作ってから渡す**。Play の「アプリのアクセス権」は、
   審査の人が自分のアカウントを作れない・使えない前提で、英語の説明と「この情報で全機能を使える」のチェックを求める。
   ログインが OAuth だけ（パスワードなし）のアプリは、その場では正しく申告できず、ここで止まる。

渡したあとにスレッド側がやること:

- りんくが Chrome の Claude の質問や確認画面をスクリーンショットで持ってきたら、**値を1つずつ正本と突き合わせてから**「この内容で合っています」と返す。
  返事もそのまま貼れる文にする。
  ★実例（2026-11-10）: Chrome の Claude がパッケージ名の例として `link.kimito.voice` を出した。正しくは `com.kimito.link.voice`。
  突き合わせずに「はい」と返していたら、変更できない名前で別のアプリができていた。
- **終わったかどうかは、りんくの言葉ではなく再実行で確かめる**（提出の workflow をもう一度回す・Play API を叩く）。
  [05 §7](05_HANDING_SCREEN_TO_HUMAN.md)「完了を人の言葉で判定しない」と同じ。

使わないもの: 本番の鍵の発行、課金・支払いの変更。これは Chrome の Claude にも渡さず、§3 の形で本人が押す。

## 4. 人に渡すスクリプト（`.cmd` / `.ps1` / 黒い画面）を作るときの決まり

1. **Enter 待ち・`pause`・`Read-Host` を置かない。** 待つのは「値がクリップボードに来た」「ファイルができた」などの**出来事**にする。
2. **状態をファイルに書く。** 今どこまで進んだか・何で止まったか・次にやること、を決まった場所（例: `~/.ai-runs/<名前>/state.json` と `log.txt`）に毎段書く。
   AI はそれを読んで続きを判断する。人に画面を読ませない。
3. **何度ダブルクリックしても安全（途中から再開）。** 済んだものは飛ばす。途中で閉じても、もう一度で続きから。
4. **`.cmd` は英数字だけ。** 日本語の案内は中身のスクリプトに出させる（コードページ切り替え直後に日本語を誤読して、
   ダブルクリックで即閉じた実損: 2026-10-28「VoiceのAI用の鍵を入れる.cmd」）。
5. **終わりを自分で確かめて報告する。** 「終わったら教えて」ではなく、スクリプトか AI が本番での確認まで行い、結果を状態ファイルに残す。
6. **そもそも渡さずに済むなら渡さない。** Remote Control の作業で AI がその PC で直接走らせられるなら、ダブルクリックも要らない。

★1〜5 を最初から満たすひな型: [`templates/hands-free-runner/`](../../templates/hands-free-runner/README.md)（2026-10-28）。
新しく人に渡すスクリプトは、ここから写して段を書き替える。

## 5. 棚卸し（2026-10-28 に実際に要った手と、無人化の道）

出典: プロジェクトのスレッド「Railway の鍵の作り直し」「無料APIクレジットへの切り替え」ほか（2026-10-24〜28）。

| 実際に要った手 | 分類 | 無人化の道（または残す形） |
|---|---|---|
| 黒い画面の下の行を読んで送る・Enter を2回押す | **AIでできる**（§2-4） | スクリプトが状態ファイルに書く→AI がフォルダ接続で読む。Enter 待ちをやめる（§4） |
| PowerShell に貼り付けて実行 | **AIでできる** | Remote Control で AI が直接実行。渡すなら英数字の `.cmd` 1つ |
| Vercel のログイン承認 | **一度だけ**（§2-3） | 長期トークン or Vercel MCP に寄せる。デプロイのたびの承認をなくす |
| Supabase の再開（Restore）と SQL の Run | **一度だけ** | 管理用トークンを1回作れば、公式の管理 API / MCP で再開・SQL 実行を AI がやる（実際に叩いて確かめてから使う）。休止そのものは定期の起こし役で防ぐ |
| 拡張の 🔄（再読み込み） | **一度だけ** | `templates/extension-self-update/`（初回の1回だけ 🔄、以後は自分で入れ替わる） |
| GitHub の請求の確認 | **AIでできる** | 公式の請求・使用量 API か、請求ページを AI が専用プロフィールで見る。毎月の要約を自動で出す |
| Claude Console のワークスペース作成・上限設定 | **一度だけ／残る** | ワークスペース作成は公式の管理 API（Admin API キーを1回）で AI ができるか確かめてから寄せる。**上限金額の変更は課金なので本人の OK＋1タップ** |
| 本番の鍵の発行（Clerk・LINE・X・Anthropic） | **残る**（各社の画面でしか発行できない・AI が作らない決まり） | 直リンク1つ→「発行」→コピー1回。受け取り・全か所への反映・本番確認は AI。期限は無期限か最長にして**年1回以下**へ |
| 鍵を作る画面での選択（スコープ・期限） | **残る** | 直リンクに選ぶ値を先に書く（「期限は無期限」）。間違えたら AI が検知して作り直しを1回だけ頼む |
| 課金・無料枠の受け取り | **残る**（課金は本人） | 1タップに絞り、受け取れたかは AI が残高で確かめる |
| ストアの Web 画面だけの初回設定（App Store Connect のプライバシー公開、Play Console のアプリ作成。2026-11-10） | **アプリごとに一度だけ** | §3.5。Chrome にいる Claude へ貼るだけの文を渡す。値の突き合わせと再実行での確認は AI |

## 6. 測り方（文章だけにしない）

- **数えるもの**: 本人に頼んだ手の回数（1作業あたり・1週間あたり）。目標は「作業ごとに0、残るものは年1回以下」。
- **機械で見られること**: [`templates/diagnostics/check-human-script-no-wait.mjs`](../../templates/diagnostics/check-human-script-no-wait.mjs)
  （`npm run diagnostics` に登録済み）が、git で管理している `.cmd`/`.bat`/`.ps1` の入力待ち（`pause`・`set /p`・`Read-Host` 等）と、
  英数字以外を含む `.cmd` を赤にする。意図的な待ち（本人の OK・パスワードの手入力）は `human-wait-ok: <理由>` で外す（理由が記録に残る）。
  ★状態ファイルを書いているか・途中から再開できるかは書き方が多様で事実として拾えないので、ひな型を使うことで満たす。
  ★本人の PC にだけある（git の外の）スクリプトはこの検査が届かない。渡す前に §4 を自分で点検し、結果をスレッドに残す。
- **機械で見られること（2）**: [`.claude/hooks/check-human-handoff.mjs`](../../.claude/hooks/check-human-handoff.mjs)（2026-11-10・拒否）が、
  人に話す道（`AskUserQuestion`・プロジェクトスレッドの `post_message`/`request_decision`/`post_widget`/`edit_message`）で
  「Git Bash に貼って実行して」「画面を送って」「PC で最新にしてから動かして」の形の依頼を、`人に頼む理由: …` の一行が無ければ止める。
  ★きっかけ: 10/28 にルールを書いた後も、返信サジェスト・会議のスレッドがコマンド貼り付けや画面送りを何度も頼んだ（Remote Control で
  自分でできた）。それまでの検査は AskUserQuestion と git 管理の `.cmd` しか見ておらず、スレッドが人に話す道に何も無かった。
  ★届く範囲: この hook はこのリポの `.claude/settings.json` で配線＝**このリポで動くセッションだけ**。クラウドで別リポ（tsuioku・
  返信サジェスト等）を開いたスレッドには `github/CLAUDE.md` の祖先読み込みも hook も届かない。別リポのプロジェクトでは、
  プロジェクトの指示（Project settings）に §2 の要点を1行入れて届ける（PC のセッションは `~/.claude/settings.json` の relay で配線できる）。
- **機械で見られないこと**: 「本当に AI ではできなかったか」は意味の判断なので検出できない。§2 のどこでだめだったかを一行書く
  （自己申告が記録に残る＝後から検査できる）ことで歯止めにする。
