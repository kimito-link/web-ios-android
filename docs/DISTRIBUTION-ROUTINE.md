## A. 理想の週次リズム（月〜金・合計40分）

固定の5ステップ。**曜日の役割を入れ替えない**（火に書いて水に見る「一晩置く」がAI無修正配信の物理的な防壁）。

| 曜日 | 分 | 人（運営者）がやること | AI（司令塔）がやること |
|---|---|---|---|
| **月** | 5 | 素材箱の先週の数字を見て「一番弱い段」を1つ決め、テーマを1文で書く（§C-4） | 素材箱を読み、先週の数字を4段の表にして提示。弱い段の候補と、それに効く投稿の型（教育／依頼）を1案だけ出す |
| **火** | 15 | AIの下書きを読み、事実と違う所・自分の言葉でない所を赤入れ。**投稿はしない** | テーマ＋実体験＋プロダクトの guardrails.md を読んで、§Bの型で X4本＋LINE1通を下書き。文字数実測・禁句grepの結果を添える |
| **水** | 5 | §C-3の5点チェック。通ったら X に投稿し、投稿1を固定。通らなければ翌週へ回す（今週は投稿ゼロで可） | 修正指示があれば反映。**AIは投稿ボタンを押さない** |
| **木** | 10 | LINE配信をOA Managerから送る（その月のプロダクトのOA 1つだけ）。届いた返信・リプに返す | 配信文の最終版と、返信の下書き（返信もキャラ/guardrails準拠） |
| **金** | 5 | X投稿の表示・リンククリック、OA Managerの経路別追加数、LINEの合言葉送信数・発送数を読み上げる | 素材箱に週次ログ1行を追記。§Dのトリガー判定を「移行／据え置き／逆トリガー」の3択で出す |

役割の線引き（変えない）:
- **人だけ**: テーマ決定・投稿・配信・返信送信・数字の読み取り・実体験の提供
- **AIだけ**: 下書き・文字数・禁句grep・ログ追記・トリガー判定・過去素材の検索
- 週40分を超えそうなら §G-12 の順番で削る。**水と金は削らない**

土日は触らない。思いついた実体験は素材箱に1行書くだけ（スマホのメモでも可。月曜に転記）。

## B. 共通の型（実体験→権威→社会的証明→CTA）

原典の対応: 実体験=返報性（先に役立つ情報を無償で渡す）＋シュガーマンの物語・欠点の先出し／権威=チャルディーニの権威（持っている証拠だけ）／社会的証明=第三者の事実／CTA=一貫性（小さな行動から）＋伝え方の「相手の得」「選択の自由」。

### B-1. X連投4本のテンプレ（1本1ブロック）

```
投稿1【実体験・手が止まった瞬間】（画像1枚）
「〈行動〉しようとして、〈場所〉で手が止まった。
〈引っかかった文言・条件〉
〈自分の状況〉の自分は、ここで〈できなかったこと〉。
調べたら、〈結論の予告〉。続き↓」

投稿2【知る・権威】
「〈誤解〉ではなかった。
〈仕組みの事実〉。〈根拠の出所（公式ページ・法令・許可・実測）〉。」
　※権威は「持っているもの」だけ: 古物商許可(第481212600002号)/法人運営/公式の確認ページ/自分で測った数字

投稿3【自分事化・社会的証明】
「〈読者が自分で確かめる手順（3ステップ以内）〉。
〈記号や結果の意味〉。〈同じ所で止まった人がいる事実 or 第三者の公式基準〉。」
　※自社実績は実売確定まで書かない。代替は「公式の基準」「同じ困りごとを持つ人の声（引用RT・リプ）」

投稿4【CTA・1種類】（URLは経路別 短縮URL）
「〈まだ分からない人・〈条件〉だった人〉へ。
LINEで『〈合言葉〉』と送ると〈最初に起きること〉。
〈次に起きること〉。見送れば0円。 <URL>」
```

### B-2. LINE配信1通のテンプレ（木・その月のプロダクトのOAだけ）

```
〈投稿1の要約2行・金額なし〉
〈投稿2の事実1行〉
迷っている方は「〈合言葉〉」と送ってください。〈最初に起きること〉。見送れば0円。
```
LINE配信は「教育」ではなく**依頼の入口**。Xで到達を測り、LINEで依頼を測る（§D・穴3対策）。

### B-3. 固定する部分／差し替える部分

| 固定（全プロダクト共通・変えるならこの文書を変える） | 差し替え（プロダクトごと） |
|---|---|
| 4ブロックの順番と本数（X4本＋LINE1通） | 実体験の本文（月1回更新・§C-4） |
| CTA形式「LINEで『〈合言葉〉』と送る」1種類。着地はLINE 1アカウント | 合言葉・LINE URL・OAアカウント |
| 金額・実績を書かない（実売確定後の続報のみ、投稿1を引用） | 権威の中身（許可・資格・公式ページ・実測） |
| 共通禁句（必ず/絶対/確実/保証/今だけ/期間限定/先着/割引/他社より/可能性が高い） | プロダクト固有禁句（`line-bot/knowledge-packs/<pack>/guardrails.md` が正本。ベストプライス=即金/高額買取/その場で買い取る/先にお支払い） |
| 発信の主語は「運営者という人」。プロダクトは解決策の一例 | 画像（投稿1の1枚だけ。作れなければ無し） |
| 水の5点チェック・金の計測 | 続報（投稿5）の条件（ベストプライス=手取り確定後） |

### B-4. 横断の軸（プロダクト別に回さない）

- 発信の主語は運営者名義のアカウント1つ（**既存の運営者Xアカウントの有無は未確認**。無ければMVPの翌月に1つ作る。MVPは既存の `@bp_kaitori` で出す＝`best-price/config.js` X_URL）。
- プロダクト公式アカウント（`@bp_kaitori` 等）は**受け皿**: 運営者投稿の引用RT＋固定ポスト＋明細の記録。自分から連投しない。
- **1ヶ月=1実体験=1プロダクト**。翌月は別プロダクトの実体験へ。「同じ人が別の困りごとも自分で解いた」という連続性がクロスセル（相手が言うまで他サービスを並べない guardrails と両立する唯一の形）。
- 各プロダクトの実体験台本は**そのプロダクトのリポの docs/** に置く（前例: `best-price/docs/CONTENT-SELLING-STORY-DESIGN.md`）。本文書は型と数値だけ持ち、台本をコピーしない。

## C. 具体機構

### C-1. X投稿（水）
1. AIの下書き4本は**文字数実測つき**（1字=2・URL=23・上限280。全本 205〜260 に収める）
2. 人が §C-3 を通す → x.com で4本を連投（リプライ連結）→ 投稿1を固定
3. 投稿4のURLは経路別短縮URL（OA Manager「友だち追加経路」`bp-x` 等。無ければ `config.js` の LINE_URL 1本）
4. **AIは投稿しない**（X APIの書き込みは使わない。非公式API・cookie方式は禁止=既存メモリ）

### C-2. LINE配信（木）
1. 配信先は**その月のプロダクトのOA 1つ**。他OAへ横流ししない（guardrails「頼まれていないのに並べない」）
2. OA Manager の一斉配信で手動送信。**月4通以内**。line-bot ハーネスのステップ配信は使わない（週1手動で足りる。件数が月50超で検討）
3. 合言葉への返答は**Webhook側 canned のみ**（OA Manager応答メッセージとの二重返信を実機で1回確認）
4. ブロック率を配信ごとに見る。1配信で **5%超なら翌週は配信を飛ばし隔週**へ

### C-3. 人間チェック（水・5分・5点だけ）
AIが先に禁句grep結果を添える（`grep -nE '必ず|絶対|確実|保証|今だけ|期間限定|先着|割引|他社より|可能性が高い|即金|高額買取|その場で買い取|先にお支払い'` ＋ 当該 guardrails.md の禁句）。人は次の5点だけ見る:
1. **事実**: 書かれた出来事は自分が体験したか（AIが補った具体は削る）
2. **数字**: 金額・実績・件数が入っていないか（許可番号・手数料・公式の記号は可）
3. **禁句**: grep結果がゼロか。1件でも翌週へ
4. **口調**: 人に話す言葉か。お金・契約の箇所でキャラ口調が出ていないか（persona.md「キャラを引っ込める場面」）
5. **CTA**: 合言葉が1種類・URLが1本か
1つでも×なら**今週は出さない**。出さない週があってよい（出す圧力がAI無修正配信を生む）。

### C-4. テーマの決め方（月・5分）
3問に答えて1文にする:
1. 先週の4段（表示→追加→合言葉→発送）で**一番弱い段**はどこか
2. 素材箱に先週足した実体験・反応で、その段に効くものは何か
3. 型は教育か依頼か（教育=表示・追加に効く／依頼=合言葉・発送に効く。§Dの段階で比率が決まる）
→ 例「△判定の人が『完済したら』と返してきた。教育: △のときに何が起きるかを1本」。
**実体験の更新は月1回**（月初の月曜）。週内は同じ実体験の別の角度（知る／確かめる／人の声／続報）で回す。

### C-5. 素材の貯め方・置き場所

| もの | 場所 | 理由 |
|---|---|---|
| **本文書（型・数値・ルール）** | `web-ios-android/docs/DISTRIBUTION-ROUTINE.md` | 正本1つ。公開リポだが数字を含まない |
| **素材箱＋週次ログ**（1ファイル・追記のみ） | `best-trust/docs/distribution/LOG.md`（新規1ファイル・private） | 表示数・追加数・依頼数は公開リポに置けない（`web-ios-android` は PUBLIC=既存設計 F3）。会社の根の private リポに置く |
| プロダクトごとの実体験台本 | 各リポ `docs/`（例 `best-price/docs/CONTENT-SELLING-STORY-DESIGN.md`） | 既存の前例に合わせる。本文書はリンクだけ |

## D. 指標と段階移行のルール

先頭列は常に**依頼側**（合言葉・発送）。表示は最後尾。到達が主役に見える表を作らない。

### D-1. 3段階と主指標

| 段階 | 主指標（これで判定） | 副指標（見るだけ） | 投稿の比率（火の4本） |
|---|---|---|---|
| **0 到達** | 週の表示数・リンクCTR・経路別LINE追加 | 合言葉数（0でよい） | 教育3:依頼1（投稿4が依頼） |
| **1 依頼** | 合言葉送信数・発送数 | 表示・追加 | 教育2:依頼2 |
| **2 影響力** | 2回目依頼・△からの再訪・引用RT/人の声の数 | 発送 | 教育2:依頼1:人の声1 |

### D-2. 移行トリガー（数値・2週連続で判定。1週の跳ねで動かない）
- **0→1**: 週の表示 **1,000以上** かつ（リンクCTR **3%以上** または 追加÷表示 **1%以上**）が **2週連続** → 翌週から依頼比率を上げ、LINE配信の冒頭を合言葉CTAにする
- **1→2**: 発送が **月3件以上** を **2ヶ月連続**、かつ実売確定の続報（投稿5）を1本出せた → 人の声（引用RT・リプ）を型に入れる。ここで初めて紹介・2回目17%の話を発信に載せる
- 移行は**1段ずつ**。飛ばさない。戻るのは §D-3 の逆トリガーだけ

### D-3. 到達だけの罠（逆トリガー・必ず適用）
- **表示が週+30%以上伸びているのに追加が2週横ばい**（±1件） → 到達を追うのをやめ、**CTA（投稿4）だけ**を1つ変える。教育投稿は増やさない
- **追加は増えるのに合言葉が3週ゼロ** → 配信文の合言葉の位置を冒頭へ。canned の返りを実機で確認（導線が壊れている疑い）
- **段階1で表示が伸びて発送が4週ゼロ** → 段階0へ戻さず、依頼投稿を2週「実体験の続報＋合言葉」だけにする実験（教育を止めて測る）
- 表示・フォロワーは**判定に使わない**。ログの「判定」列に「到達のみ伸び」と書いて、来週直す1つを必ず依頼側にする

### D-4. 「1つ変えたら測ってから次」
週に変えるのは1つ（投稿文・配信文・画像・経路URLのどれか1つ）。ログの「来週直す1つ」に書いた以外は触らない。2つ同時に変えたらその週の判定は「無効」と書く。

### D-5. 飽き防止（穴3）
- 毎週、火（到達）と木（依頼）の**両方を同じ行で測る**。依頼0の週も「合言葉0」と書く（書かないと教育に逃げる）
- 依頼が来た週は素材箱に**反応を1行**（次の実体験の種）
- **8週連続で合言葉ゼロ**なら、型でなく**実体験（プロダクト）を替える**。ルーティン自体は止めない

## F. 捨てた案と理由

1. **プロダクト別に5本のルーティンを回す** — 週40分×5で破綻。フォロワーも混乱。1ヶ月1実体験のローテに置き換え
2. **曜日ごとに媒体を割る運用表（月X・火IG・水TikTok…）** — 初めての人が最初に作って最初に捨てる表。媒体はX＋LINEの2つに固定、IGは保存装置として台本側で扱う
3. **AIが投稿・配信まで自動化**（X API書き込み／line-botステップ配信） — 非公式APIはBANリスク（既存メモリ）、正規APIは書き込み有料。何より水の「一晩置く」が消える。件数が月50超まで手動
4. **フォロワー数を主指標にする** — 到達だけの罠そのもの。既存ダッシュボード設計§Fの副指標に留める
5. **「CTR3%到達で即切替」の単週判定** — 表示200件で3%は6クリック。最低表示1,000＋2週連続を条件にした
6. **教育コンテンツを4週続けてからCTA** — 穴3の直行便。毎週投稿4とLINE配信で依頼を測る構造にした
7. **週次ログをスプレッドシートに** — AIが読み書きしにくく、素材箱と分離する。private リポの md 1ファイルに統合
8. **週次ログを `web-ios-android` に置く** — PUBLIC リポ（既存設計 F3）。数字を置けない
9. **ココナラ★5.0（681件）を権威に使う** — 外部転載の適法性が未確定（`DESIGN-two-channel-acquisition-strategy-2026-09-01.md`）。確定するまで発信に載せない
10. **禁句チェックのスクリプトを新規作成** — grep 1行で足りる。ツールを増やすと「ツールが緑=安全」に倒れる
11. **不可判定（△×）の人へ他プロダクトを配信** — guardrails「頼まれていないのに並べない」に反する。横断は「翌月の実体験」でしかやらない
12. **投稿5（続報）を先に書いておく** — 実売確定前に金額・実績の形を作ると詐称の温床。確定後に投稿1を引用して書く

## G. 地雷と回避策

1. **穴1: 到達だけ追って売上に繋がらない** → ログの先頭列を合言葉・発送にし、表示を最後尾に。移行は §D-2 の数値（表示1,000＋CTR3%/追加1%・2週連続）でしか起きない。§D-3 の逆トリガー（表示+30%で追加横ばい2週→CTAだけ変える）を金曜のAI判定に必ず含める
2. **穴2: AI無修正配信** → 火に書いて水に出す（物理的に一晩置く）。AIは投稿ボタンを押さない。水の5点（事実・数字・禁句・口調・CTA）に1つでも×なら**その週は出さない**。禁句grepはAIが先に回し、結果ゼロを人が目で見る。プロダクト固有禁句は guardrails.md からコピーせず都度読む
3. **穴3: 教育寄りで中期売上が長期化し飽きる** → 毎週、投稿4（依頼）とLINE配信（依頼）が構造上必ず入る。到達と依頼を**同じ週・同じ行**で測る。8週合言葉ゼロで実体験を替える（ルーティンは止めない）
4. **実績詐称** → 金額・件数・「売れた」は実売確定後の投稿5のみ。運営者自身の売却は自社サービス経由ではない（自分で売り先を比べた）ので成約実績として書かない。LPの「実績の数字はまだ出せません」は残す
5. **画像の一般化ミス** → `x-zandebug.png` の3段落目はキャリア分割の話でPaidy残債には当てはまらないので訂正済み。今後の画像も投稿前に単体で成立するか見る
6. **X文字数** → 1字=2・URL=23・上限280。赤入れで1文足すたびAIが数え直す
7. **経路URL** → 投稿4のURLは経路別短縮URL。作れなければ `config.js` LINE_URL 1本。`/r/<ref>` はLIFF未設定で使わない
8. **合言葉が返らない** → 木の配信前（水）に自分のLINEから合言葉を送り canned の返りを実機で確認。OA Manager応答メッセージとの二重返信も同時に見る。返らなければ導線が最初から壊れている
9. **公開リポに数字** → 表示・追加・依頼数・フォロワー数は `best-trust/docs/distribution/LOG.md`（private）にだけ書く。本文書には閾値以外の数字を書かない
10. **運営者アカウント未確認** → 既存の運営者名義Xの有無は未確認。MVPは `@bp_kaitori` で出し、翌月の月曜に「作る／既存を使う」を決める。今週は決めない（1つ変えたら測ってから次）
11. **LINEブロック** → 配信は月4通以内。1配信でブロック率5%超なら隔週へ。配信は依頼の入口であり教育の場ではない
12. **週40分を超える** → 削る順番: Instagram → LINE配信を隔週 → X投稿を4本から2本（投稿1と投稿4だけ） → 画像なし。**水のチェックと金の計測は最後まで削らない**（削ると無修正配信と到達罠が同時に戻る）
13. **同時に複数を変える** → 週に変えるのは1つ。2つ変えた週は判定「無効」とログに書く
14. **他リポの正本を書き換える** → 禁句・トーン・手数料・流れは guardrails.md / persona.md / config.js が正本。発信のために別の言い方を作らない。矛盾を見つけたら先に正本を直してから出す（LPの「○」→「○または−」が前例）
15. **AIが実体験を補完する** → 下書きで「それらしい具体」を足すのがAIの癖。水の1点目「自分が体験したか」で削る。素材箱に無い出来事は書かない
