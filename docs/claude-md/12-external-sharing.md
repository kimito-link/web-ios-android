## ★社外の人に渡すページは、自社ドメインの https に置く（2026-09-08 追記・best-price から書き戻し）

> ユーザーの言葉: **「パスワード付きを教えるURLを https の形で教えるのが普通では。なんでこんな回りくどいことするの？」**
> 取引先に渡す説明ページを Claude の Artifact（`claude.ai/code/artifact/…`）で作って渡そうとし、指摘された。

- **Artifact は閲覧に Claude のログインが要る。** 社外の人・取引先・顧客に渡すページには使わない。
  自分専用の下書き、または同じ Claude アカウントの中だけで見るものに限る。
  ★判断の型: 「誰が開くか」を先に決める。Claude を持っていない人が1人でも居るなら Artifact は不採用。
- 渡す先が社外なら、最初から**自社ドメインの https URL** に置く（Vercel の静的ページ。ドメイン接続は上の「1コマンド」）。
  実例: `https://bestprice-kaitori.com/uragawa/`（しくみの説明・パスワード付き）。
- **パスワードを掛けたいときの型**: 本文をパスワード由来の鍵（PBKDF2 → AES-GCM）で暗号化して HTML に埋め込み、
  ブラウザ内で復号する。サーバー上でもソースを見ても本文が読めない。`noindex` を付ける。
  実装: `../best-price/tools/uragawa/`（`shell.html`＝入力画面と復号、`build.mjs`＝暗号化と往復確認・平文漏れ検査）。
  ★本文（平文）は public リポに commit しない（`.gitignore`）。
  ★Cloudflare Access で鍵を掛ける方法もあるが、Access 権限のトークンが要る（上の権限表）。静的1ページなら暗号化埋め込みの方が依存が無い。
- **社外向けの説明は、小学生でもわかる言葉で書く**（同日の2つ目の指摘: 「この説明もわかりづらい」）。
  「委託」「落札」「PBKDF2」のような言葉を、「代わりに売る」「売れる」「パスワードで鍵をかける」に置き換える。
  図は残してよい。文章のほうを短く・やさしくする。上の「キャラで親しみやすく」節と同じ基準。
